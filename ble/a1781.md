# A1781 (F2600) BLE

The SOLIX F2600 (A1781). This page owns the BLE-specific facts of the product; the command payloads (opcodes, TLV tags, scales) are owned by the MQTT page [../mqtt/a1771.md](../mqtt/a1771.md) of the product family (there is no page for this exact product) and are not repeated here. The frame, fragmentation and encryption are on [protocol.md](protocol.md), the negotiation on [handshake.md](handshake.md).

Evidence is the asm of 3.24.3 (`file.dart @0xADDR`, relative to `charging/ble/device/` unless a path is given). Pool lists such as `[0, 0x5e]` are real values. A row that says `no` in the column `on the MQTT page` means the opcode is not mentioned on the linked page; it can still be a command that also goes over MQTT.

Notes on this product:

- `A1781AnkerDevice` extends `A1771AnkerDevice` and `A1781DeviceController` extends `A1771DeviceController`; the WiFi selection page of this family is `zx_select_wifi_logic.dart` (`charging/ui/page/device/a1781/wifi/select_wifi/`), which references `ZXOpcodeType`; which members it uses was not decoded.
- The controller references `004e`, an opcode that no other controller references.
- There is no MQTT page for this product; the closest is the A1753 page [../mqtt/a1753.md](../mqtt/a1753.md), which has an A1781 note.
- Negotiation, app side: `A1781AnkerDevice` (class id 8485) has `ZXBleFeature` in its `extends` line and `A1781` is not a registered SDK product code, so `BleHandler` picks `BleHandlerImpl1`, whose `_authDevice` starts the Dart `ZXBleConfer`. Which of the three conferers then runs depends on the capability response, not on the product ([handshake.md](handshake.md#which-implementation-runs-for-a-product)).

## Commands

### Device-class methods

#### Purpose

Records that the device classes of this product add no opcode methods: the handshake, WiFi and OTA methods are inherited from the parent classes on [a1771.md](a1771.md).

#### Upstream name

none for the sequence; the opcode names are the app's `ZXOpcodeType` members (no upstream name).

#### Opcode

No pool opcode list in `a1781_anker_device.dart`; the methods and opcodes are those of [a1771.md](a1771.md).

#### Direction

both: requests go app to device, the responses (`08xx` in the common map, [handshake.md](handshake.md#opcode-pairs)) come back device to app.

#### Packet framing

[protocol.md](protocol.md#frame-on-ble); the handshake frames carry the flag bits of [protocol.md](protocol.md#opcode-byte-0-flags).

#### Handshake prerequisite

The rows of group `handshake` are the handshake. Which conferer runs (`SecureEcdhConfer`, `EcdhConfer` or `AesConferV1`) is chosen from the capability response, not from the product: [handshake.md](handshake.md#capability-negotiation-response). The other rows are ordinary commands that need a completed handshake for encrypted frames.

#### TLV tags

The handshake payloads are positional bytes or single tags and are not per-product; they are described in [handshake.md](handshake.md#capability-negotiation-response) and [handshake.md](handshake.md#the-three-conferers). The payloads of the WiFi, OTA and status-request rows were not decoded for this page.

#### Example

none: no capture of a handshake exists in this repository.

#### Related API endpoint

none: the handshake has no MQTT twin and the product has no MQTT page.

#### Since/changed

3.18.0: the same device-class files. 3.24.3: the opcode set of the device-class file(s) is unchanged; the `ProductModel` of A1781 existed in 3.18.0 (see [protocol.md](protocol.md#since-3180)).

#### Known unknowns

none.

BLE is unavailable while the device is on WiFi; see `ble/protocol.md` (community finding, see protocol.md; not asm-traced).

#### Device-tested by

none.

#### Direction

app to device for the requests; the matching responses and the periodic status push `0405` (`postDeviceAllInfoReq` in the charging map, [protocol.md](protocol.md#zx-opcode-names)) come back device to app.

#### Packet framing

[protocol.md](protocol.md#frame-on-ble) and [protocol.md](protocol.md#fragmentation); the controller's `sendCommand` waits 5 s by default ([protocol.md](protocol.md#timeouts-and-limits)).

#### Handshake prerequisite

A completed handshake is needed for encrypted commands: the frame builder encrypts only when the device has a key ([protocol.md](protocol.md#payload-encryption)).

#### TLV tags

Owned by the linked MQTT page: [../mqtt/a1771.md](../mqtt/a1771.md). Opcodes marked `no` in the table have no tag table there. Their payload shapes, read from the controller methods (shape definitions: [protocol.md](protocol.md#controller-send-wrappers)): `setDeviceUpdateEnergy` (`0057`) sends tags 0xA2 and 0xA3; one-byte setters: `setEnergyMode` (`004e`), `setAcFrequency` (`004d`), `setCarSwitch` (`004b`), `setAcSwitch` (`004a`), `setScreenSwitch` (`0052`), `setSosMode` (`004f`), `setTempUnit` (`0050`), `setLcdLight` (`004c`); two-byte setters (`intToList2`): `setDeviceScreenTime` (`0046`), `setAcChargePower` (`0044`); four-byte setters (`intToList4`): `setCarCountDownTime` (`0043`), `setAcCountDownTime` (`0042`); requests without payload: `getAcCarCountDownTime` (`0041`), `setReset` (`0051`); `getAllDeviceInfo` (`0040`, `a1781_device_controller.dart @0x40f439c`) is the status request: empty payload, frame by `ZXCommandTransformer.formatCommand`. The response of a request is not handled in these methods (they return Null after the send).
