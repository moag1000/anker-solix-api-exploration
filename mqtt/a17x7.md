# A17X7 MQTT commands

Smart meter (A17X7, with the variant A17X7US): the 0405 status message and the work-info parser of the 3.24.3 app. The envelope, topics, frame layout and data type codes are owned by [envelope.md](envelope.md) and not repeated here. The meter has no SET opcode in the audit; only the realtime trigger is known from upstream.

Evidence rows are written `audit row N` and refer to [../docs/audit/BLE_COMMAND_MAP.md](../docs/audit/BLE_COMMAND_MAP.md); `file.dart @0xADDR` is 3.24.3 asm. Tag keys and indexes follow the Smi rule in [../METHODOLOGY.md](../METHODOLOGY.md#smi-rule-reading-numbers-from-blutter-output). Names are upstream's (`api/mqttmap.py`, `A17X7` block lines 5315-5329); a name of ours is marked `(no upstream name)`. Parser file: `charging/ble/device/A17X7/a17x7_device_commands.dart`. Store offsets are Blutter byte offsets (not Smi-affected); every tag in the tables below was seen as an `indexString` argument, hex equals the decimal argument.

## Commands

### 0405 status message (parseDeviceAllInfo)

#### Purpose
Periodic status of the meter: identity, firmware, grid power and the import/export energy counters.

#### Upstream name
`"0405"` of `A17X7`, topic `param_info` (`mqttmap.py` lines 5317-5328), upstream-confirmed.

#### Command code
`"0405"`, parsed by `A17X7DeviceCommands.parseDeviceAllInfo` @0x4858720 (size 0x10c8). Asm-traced for the parser; upstream-confirmed for the message id.

#### Direction
device→app. Tag: asm-traced.

#### Topic pattern
[envelope.md](envelope.md#topics): `dt/anker_power/A17X7/<sn>/param_info`.

#### Payload fields
The parser reads `fe`, `a2`, `a3`, `a5` to `ad` and `fd` (audit rows 264-276). `ac` and `ad` store into the same model fields as `a8` and `a9` (audit rows 270, 271, 274, 275): they are alternate sources for the same two values; upstream keeps `ad` only as a comment.

#### Example
synthesized. Not a capture; layout only.

```text
ff 09 <len> 03 01 0f 04 05 | a1 01 22 | a2 <len> 00 <device_sn> | a8 05 03 <grid_to_home> | a9 05 03 <pv_to_grid> | fe 05 03 <ts> | xor
```

#### Related API endpoint
none (MQTT only).

#### Since/changed
Every tag keeps its role. Store offsets moved in 3.24.3 (audit rows 266-275): in most rows by 0xC (for example `a5` 0x3db to 0x3e7, `a7` 0x2d7 to 0x2e3), `a8`, `a9`, `aa`, `ab` by 0x18 (0x477 to 0x48f, 0x47b to 0x493, 0x47f to 0x497, 0x483 to 0x49b), `a3` by 0x8 (0x187 to 0x18f); `a6` (0x7b) did not move. Changed since 3.18.0.

#### Known unknowns
- Tag `fd`: binding and meaning (audit row 276).
- The divisors of the energy tags `aa` and `ab` (upstream factor 0.01) and of the power tags are not audited for this parser.
- Roles of `a3`, `a5` (no upstream names).

#### Device-tested by
none recorded in this repo for the meter.
