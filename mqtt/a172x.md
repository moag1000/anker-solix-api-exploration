# A172X MQTT commands (C300 family)

SOLIX C300 / C300X / C200 family (A1722 to A1729; the audited parser is A1726, C300 DC): the 0405 status message and the PPS single-value setters. The envelope, topics, frame layout and data type codes are owned by [envelope.md](envelope.md) and are not repeated here. The other PPS products have their own pages: [a1771.md](a1771.md), [a1780.md](a1780.md), [a1790.md](a1790.md).

Evidence rows are written `audit row N` and refer to [../docs/audit/BLE_COMMAND_MAP.md](../docs/audit/BLE_COMMAND_MAP.md); `file.dart @0xADDR` is 3.24.3 asm. Opcodes are the hex strings of the Dart source (pool lists `[0, 0x4a]` are the same two bytes, never halved); tag keys are halved Smi immediates (raw 324 is tag `a2`), per the Smi rule in [../METHODOLOGY.md](../METHODOLOGY.md#smi-rule-reading-numbers-from-blutter-output). Names are upstream's (`api/mqttmap.py`, `api/mqttcmdmap.py`); a name of ours is marked `(no upstream name)`. Upstream product names: `api/apitypes.py` lines 682-688.

## Commands

### 0405 status message (param_info)

#### Purpose
Periodic status of a SOLIX C300 DC (A1726): USB ports, DC and solar power, battery state, firmware parts and display settings.

#### Upstream name
`_A1728_0405` (topic `param_info`), `mqttmap.py` lines 242-311; the A1726 entry binds it to `"0405"` at line 4193 (A1728 binds the same map at line 4229; A1722 and A1723 use `_A1722_0405`, A1725 and A1727 use `_A1725_0405`, A1729 uses `_A1729_0405`), upstream-confirmed. Product names: A1722 C300, A1723 C300X, A1725 C200(X), A1726 C300 DC, A1727 C200 DC, A1728 C300X DC, A1729 C200X DC (`apitypes.py` lines 682-688).

#### Command code
`"0405"`, parsed by `A1726DeviceCommands.parseDeviceAllInfo` @0x3b35770 (size 0x1c3c; `charging/ble/device/A172X/172X/a1726_device_commands.dart`). The same file has `parseCountDownTimeDC` @0x3b34844 and `parseSwitchStateInfoDC` @0x3b34c94 (function start and size from the asm header; their fields are not in the audit). Asm-traced for the parser; upstream-confirmed for the message id.

#### Direction

#### Topic pattern
[envelope.md](envelope.md#topics): `dt/anker_power/A1726/<sn>/param_info`.

Type, width and scale of every row, new read 2026-10-20 (`a1726_device_commands.dart` @0x3b35770, tag blocks @0x3b357d0 to @0x3b37274): all numeric tags go through `CmdUtil::listToInt`, whose result is a 64-bit unboxed integer (real value, no Smi halving), and each result is stored with a 32-bit store into a tagged slot at the raw object offset shown in the type column. The only arithmetic in the whole parser is the signed 8-bit conversion of `b5` and the compares against raw 64-bit values (`cmp x0,#1` for the bool tags, `cmp x2,#4` for `c8`); there is no multiplication or division, so the upstream factors `a3` 0.1 and `af` 0.001 are not applied by the app parser (app side). `b1` is read with `listToInt` and not stored; `b2` is stored at 755, `b3` at 759, and `b4` at 767 and also passed to `getMainVersion` (@0x3b361dc). `bd`, `be`, `c0`, `c2`, `bf`, `ca` and `cc` are bools (`bf` is stored twice, at 851 and 939; `b7` twice, at 803 and 991). `c4` is stored at 447 and `c5` at 455; `c7` at 943; `c9` at 963; `cb` at 451; `cd` at 783; `c1` at 999.

### PPS setters 0043 to 0079 (single-value commands)

#### Purpose
Writes one device setting of the C300 family: output switches, display and light settings, timeouts, charge power, port memory.

#### Upstream name
Upstream binds each opcode to a generic command constant, see the table (`mqttmap.py` PPS blocks, lines 4110-4760); upstream has no constant for `004d` or `0075` in any PPS block. Several upstream constant names differ from the app function names (for example `0043` is `CMD_DC_OUTPUT_TIMEOUT_SEC` upstream and `setCarCountDownTime` in the app); both are listed. Upstream constants are described on [upstream_commands.md](upstream_commands.md).

#### Command code
Hex strings below are the pool lists of the Dart source (never halved). The functions live in `charging/ble/device/A172X/172X/a172x_device_controller.dart`. Asm-traced for the opcode and the payload width; upstream-confirmed for the names.

#### Direction

#### Topic pattern
[envelope.md](envelope.md#topics): `cmd/anker_power/<pn>/<sn>/req`.

The unit names (seconds, minutes, watts) and the value sets are upstream's: the setters do not show units, and the audit rows state that the unit names are not visible in asm (rows 253-256, 260).

#### Known unknowns
- `004e` `setEnergyMode` is UNVERIFIABLE (audit row 249): the pool list `[0, 0x4e]` exists, no controller function of that name uses it, and only the UI logic `a1780p_home_logic.dart` calls a method of that name. The A1780 file `a1780_commands.dart` also holds a static `setEnergyMode` @0x3c9de40 that returns a 14-element byte list (a BLE command array, not decoded here and not an MQTT opcode string).
