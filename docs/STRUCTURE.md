# Information Architecture and Fact Ownership

This page defines where every kind of fact lives in the rebuilt repository and how the existing files migrate there. The rule is single source: a fact lives on exactly one owner page, and every other page links to it. Tags, the Smi rule and the page header format are defined in [../METHODOLOGY.md](../METHODOLOGY.md); the reader paths that depend on this layout are in [PERSONAS.md](PERSONAS.md).

## Target layout

```
README.md                 entry: role paths, use-case index, version matrix, what changed in 3.24.3
GLOSSARY.md               terms (Task 4.1)
METHODOLOGY.md            how facts are produced, Smi rule, tags
CHANGELOG.md              per-rework entries + Errata
api/<service>/<endpoint>.md   ONE page per endpoint (owner of payload facts)
api/param_types.md        master table (owner of param_type/cmd facts)
api/errors.md             error code catalog (Task 4.2)
api/auth.md               login, headers, token, encryption pointer
api/encryption.md         ECDH payload encryption
mqtt/<pn>.md              decoder per product (owner of MQTT field facts), mqtt/envelope.md
ble/<pn>.md, ble/protocol.md, ble/handshake.md
flows/<name>.md           step traces, link to owners
devices/<pn>.md           product page: links to api/mqtt/ble owners + device-tested status
models/<class>.md or models/<group>.md   response/request models (owner of field lists)
reference/enums.md, reference/business_rules.md, reference/validation_model.md
data/endpoints.json, data/models.json, data/param_types.json, data/errors.json   machine-readable, generated
tools/                    scripts
docs/                     personas, structure, issues, audit tables, plans
```

Each directory has a `README.md` index stub: [api](../api/README.md), [mqtt](../mqtt/README.md), [ble](../ble/README.md), [flows](../flows/README.md), [devices](../devices/README.md), [models](../models/README.md), [reference](../reference/README.md), [data](../data/README.md), [tools](../tools/README.md). Pages named in the layout above do not exist yet unless a stub is linked here; they are created by later tasks.

## Ownership rule

Payload facts live in `api/<service>/<endpoint>.md`; `devices/` and `flows/` link, they never copy.

| Fact type | Owner page |
|---|---|
| Endpoint payload and parameters | `api/<service>/<endpoint>.md` |
| param_type and cmd values | `api/param_types.md` |
| Error codes | `api/errors.md` |
| Auth headers and login | `api/auth.md` |
| MQTT field maps | `mqtt/<pn>.md` |
| MQTT envelope | `mqtt/envelope.md` |
| BLE opcodes and TLV | `ble/<pn>.md` (handshake: `ble/handshake.md`; frame format: `ble/protocol.md`) |
| Model fields | `models/` |
| Enums and product codes | `reference/enums.md` |
| Business rules | `reference/business_rules.md` |
| Validation (GET to SET) | `reference/validation_model.md` |
| Flows | `flows/<name>.md` (links only, no payload copies) |
| Devices | `devices/<pn>.md` (links and device-tested status only) |
| Machine-readable data | `data/*.json` (generated by `tools/`) |

If a fact is needed on a non-owner page, link to the owner. When an owner page is corrected, grep for the old value across the repository before committing.

## Naming conventions

- File names are lowercase with underscores.
- Endpoint pages are named exactly after the last URL segment, for example `set_site_device_param.md`.
- PN pages use the lowercase product number, for example `a17c5.md`.
- Service directories are named exactly after the URL prefix, for example `charging_hes_svc/`.
- Upstream names (apitypes.py keys, mqttmap names) win over ours.

## Page-length and split rules

- No page is longer than 600 lines.
- Every page longer than 150 lines has a table of contents.
- Oversized files are split along ownership lines. `BLE_COMMAND_MAP.md` (2402 lines) splits into `ble/protocol.md`, one `ble/<pn>.md` per product number, and `mqtt/envelope.md`; the per-PN split is listed in the migration map below.
- Old files are not deleted until Phase 4 (Task 4.7). Until then each gets a top banner "superseded by ..." once its content has moved.

## Notes on consistency with PERSONAS.md

- The brief counted 14 root docs; the repository has 15 because `METHODOLOGY.md` was added in an earlier task. It is listed as kept.
- PERSONAS.md maps `VALIDATION_MODEL.md` to `flows/<name>.md`. The layout above (and the brief) puts the validation model on `reference/validation_model.md`; flow pages link to the ranges there. PERSONAS.md should be aligned in a later task.
- PERSONAS.md maps the MQTT parts of `devices/smart_plug.md` to `devices/<pn>.md`; here MQTT field facts belong to `mqtt/<pn>.md` and the device page only links.
- PERSONAS.md names `reference/` without a file; the owner files are `reference/enums.md`, `reference/business_rules.md` and `reference/validation_model.md`.
