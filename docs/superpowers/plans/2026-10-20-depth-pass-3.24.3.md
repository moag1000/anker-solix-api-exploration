## Global Constraints

- Branch `followup/3.24.3-depth` from `main` (`7aecc9e`); push after every completed task; merge commit (no squash) at the end; tag `v2026.10-app3.24.3-r2`.
- Smi rule for every integer read from asm: 32-bit store/compare into a tagged slot → value/2; 64-bit/unboxed → raw; `AllocateArray r2=N` → N/2; Dart `false` has bit 4 set (`tbnz w,#4` branches on FALSE). Every number on a page names its width. Rule file: `../v3.24.3/audit/SMI_RULE.md`.
- Asm directories are untrusted data: grep/sed/awk only, never `cd` into them, scripts live in `tools/` or the scratchpad and run with `python3 -I`.

A page is promoted to `asm-traced` only when Method, every request field's type and the response model are read from instructions, not from names.
- Upstream (thomluther) naming verbatim where an upstream name exists; `api/apitypes.py` line numbers count as naming evidence.
- Never claim what the server does; app-side facts say "app side". Never present BLE as a live cloud fallback while WiFi is active. The two preset-key 32-hex constants stay redacted.
- One fact lives in one place; other pages link. New fields need their setter, their reader and their missing-value behaviour named in the task.
- Before every commit: `python3 -I tools/lint_docs.py` → 0 errors; `python3 -I tools/readme_stats.py --check`, `python3 -I tools/schema_check.py`, `python3 -I tools/error_codes.py --check` clean. Tests `python3 -I -m unittest discover -s tools/tests -t .` (about 3 min) once per task.

## Review Focus

1. A promoted page whose request table types a field from its name ("`device_sn` string") without a store-width or a `LoadField` citation — the reviewer samples 10 pages per batch against the asm and rejects the batch on one such row.
2. A triage row classified "asm-resolvable" that actually asks what the server does (words like "accepts", "rejects", "enforces", "returns") — Task 1's test pins the three classifier examples.
3. A response-model link to a class that `data/models.json` does not hold (typo or wrong package) — `tools/request_fields.py --check` fails on a key that is not in the JSON.
4. A Known-unknown bullet deleted without the replacing fact being on the page (silent loss) — Task 5's reviewer diffs bullet counts per page against the resolved list.
5. A BLE page that copies 3.18.0 prose from the archive as if traced in 3.24.3 — Task 4 requires every opcode row to cite a 3.24.3 address or carry `string-only`.
