# A91B2 MQTT commands (240 W Charging Station)

240 W Charging Station (A91B2): the status tags and the setters. It shares the Prime Charger protocol family with [a2345.md](a2345.md), which owns the per-port structure. The envelope, topics, frame layout and data type codes are owned by [envelope.md](envelope.md).

Evidence rows are written `audit row N` and refer to [../docs/audit/BLE_COMMAND_MAP.md](../docs/audit/BLE_COMMAND_MAP.md); `file.dart @0xADDR` is 3.24.3 asm. Tag keys are halved Smi immediates (per the Smi rule in [../METHODOLOGY.md](../METHODOLOGY.md#smi-rule-reading-numbers-from-blutter-output)). Names are upstream's (`api/mqttmap.py`); a name of ours is marked `(no upstream name)`.

## Commands

### parseDeviceAllInfo (status tags, upstream message 0a00)

#### Purpose
Decodes the full status of a 240 W Charging Station (A91B2): six port blocks, two AC switches, settings and the version.

#### Upstream name
`"0a00"` of A91B2 (`mqttmap.py` lines 5574-5710; status request `"0200"` at line 5530; per-second `"0303"` = `_A2345_0303` at line 5572), upstream-confirmed. The old doc mentions A91B2 only as "A91B2 has this as 4th port" in the A2345 table; no audit row covers the A91B2 status parser.

#### Command code
Message id (app side, re-read 2026-10): in the A91B2 controller `OPCODE_KEY == [0xa, 0]` (`listEquals` @0x3b5d310, log `getAllDeviceInfoRes` @0x3b5d31c) calls `parseDeviceAllInfo` @0x3b5d3e4, and `OPCODE_KEY == [0x3, 0x3]` (@0x3b5d63c, log `uploadDCPortState` @0x3b5d654) takes the port branch, so the ids are 0a00 and 0303 as in upstream (opcode key: [iot.md](iot.md#frame-decode-and-opcode-dispatch)). `A91B2DeviceCommands.parseDeviceAllInfo` @0x3b5f3cc (size 0xcfc; `charging/ble/device/A91B2/a91b2_device_commands.dart`) reads 21 `indexString` arguments: `a2` to `b5` (20 tags) and `fe` (new read, tag numbers only). It calls its `parseChargePortInfo` @0x3b5ed54 six times (@0x3b5f68c, @0x3b5f6f8, @0x3b5f764, @0x3b5f7d0, @0x3b5f83c, @0x3b5f8a8). The class `A91B2AnkerDevice` has its own mixin chain and does not extend the A2345 class (class header, `a91b2_anker_device.dart` line 8). Asm-traced for the tag set.

#### Direction
device→app. Tag: asm-traced.

#### Topic pattern
[envelope.md](envelope.md#topics): `dt/anker_power/A91B2/<sn>/state_info` for `0303`; the topic of `0a00` is not bound by an audit row.

#### Payload fields
Compared with [a2345.md](a2345.md): A91B2 has no tag after `b5` (A2345 also reads `b7` to `bf`), and upstream has two AC switches (`aa`, `ab`) where A2345 has five USB switches (`aa` to `ae`). The per-port sub-parser `parseChargePortInfo` @0x3b5ed54 (size 0x1f4) uses the same windows as A2345: minimum payload 7 bytes (`cmp x1,#7` @0x3b5ede8) and `sublist` windows with raw ends 6, 10 and 14 (@0x3b5ee74, @0x3b5eeb8, @0x3b5eefc), which halved are bytes [1, 3), [3, 5) and [5, 7); the field table is owned by [a2345.md](a2345.md).

#### Related API endpoint

#### Since/changed
No 3.18.0 comparison was made for the A91B2 parser (no audit row).

#### Known unknowns
- Which message id the device sends: the app binds the parser to `0a00` and the port branch to `0303` (Command code); the id on the wire is not captured here (device test row 96).
- Names and types of `a3` and `ac` to `b5` (upstream has no name).
- The audit rows 329-341 are the A2345 parser; whether A91B2 tags `b0` to `b5` mean the same as in A2345 is not known.

#### Device-tested by
none.

### Setters (A91B2 controller)

#### Purpose
Sets the charging mode, the AC port timer and relay, the clock format and the screen saver of a 240 W Charging Station.

#### Upstream name
Upstream has `"0207"` (port switch with `ac_1_switch` and `ac_2_switch` as the state names, `mqttmap.py` lines 5531-5561), `"0200"` status request and `"020b"` realtime trigger for A91B2 (lines 5530 and 5562), upstream-confirmed; the app functions could not be matched to these opcodes from the audit.

#### Command code
Opcode strings are not in the audit rows 324-328 (tag keys only); the functions live in `charging/ble/device/A91B2/a91b2_device_controller.dart` (function start and size from the asm header). Asm-traced for tag keys.

#### Direction
app→device. Tag: asm-traced.

#### Topic pattern
[envelope.md](envelope.md#topics): `cmd/anker_power/A91B2/<sn>/req`.

#### Payload fields
Tag keys are halved Smi immediates (324 is `a2`). The old doc listed the A2345 and A91B2 functions together; the audit separated them (rows 324-328).

| function | tags | width | opcode | source |
|---|---|---|---|---|
| `setChargingMode` @0x3ef86d4 (size 0x1e4) | a2 only | not recorded | not in the audit | audit row 324; @0x3ef8720 (the A2345 version also writes `a3` and `a4`) |
| `setACPortCountdownTask` @0x3f01dec (size 0x6b4) | a2, a3 | a3 `intToList4` (4 bytes) | not in the audit | audit row 325; @0x3f022e0, @0x3f02348 |
| `setACRelaySwitch` @0x3f03980 (size 0x2a0) | a2, a3 | not recorded | not in the audit | audit row 326; @0x3f03a10, @0x3f03a78 |
| `setClockFormat` @0x3f0dd4c (size 0x12c) | a2 | not recorded | not in the audit | audit row 327; @0x3f0dd98 |
| `setScreenSaverSwitchAndTheme` @0x3f0cbb8 (size 0x10c) | a2 only | not recorded | not in the audit | audit row 328; @0x3f0cc18 (the A2345 variant `setScreenSaverSwitchAndThemeByUrl` writes `a2` to `a7`) |

#### Example
synthesized. `setACPortCountdownTask` with a 4-byte `a3` (type 3, see [envelope.md](envelope.md#data-type-codes)); not a capture.

```text
a1 01 22 | a2 02 01 <v> | a3 05 03 <seconds 4 bytes> | xor
```

#### Related API endpoint
none (MQTT only).

#### Since/changed
The functions and tag keys were confirmed in 3.24.3 (audit rows 324-328); no 3.18.0 difference was recorded.

#### Known unknowns
- The opcode of each setter (not in the audit).
- The widths of the values that are not `intToList4`, and the meaning of `a3` of `setChargingMode`: the A91B2 function writes only `a2`.

#### Device-tested by
none.
