# A1790 MQTT commands (F3800)

SOLIX F3800 (A1790, A1790P): the 0405 status message, the expansion-battery model (SubBatteryInfo) and four setters. The envelope, topics, frame layout and data type codes are owned by [envelope.md](envelope.md); the PPS single-value setters shared with the C300 family are on [a172x.md](a172x.md); the base tags of the PPS chain (A1790 extends A1771) are on [a1771.md](a1771.md).

Evidence rows are written `audit row N` and refer to [../docs/audit/BLE_COMMAND_MAP.md](../docs/audit/BLE_COMMAND_MAP.md); `file.dart @0xADDR` is 3.24.3 asm. Tag keys are halved Smi immediates (per the Smi rule in [../METHODOLOGY.md](../METHODOLOGY.md#smi-rule-reading-numbers-from-blutter-output)); store offsets are Blutter byte offsets. Names are upstream's (`api/mqttmap.py`); a name of ours is marked `(no upstream name)`. The structure rows 89-90 (SubBatteryInfo) are owned here; rows 91-97 (OutputPortInfo) are on [a2345.md](a2345.md).

## Commands

### 0405 status message (param_info)

#### Purpose
Periodic status of a SOLIX F3800 (A1790): AC, USB and PV power, battery and expansion state, firmware parts, generator and port settings.

#### Upstream name
`_A1790_0405` (topic `param_info`, `mqttmap.py` lines 1471-1548; bound for A1790 at line 4699 and for A1790P at line 4738, upstream-confirmed). A second map `_A1790_040a` (lines 1550-1719) and `_A1790_0410` (line 1720) carry the expansion and other messages; they have no audit row.

#### Command code

The class `A1790AnkerDevice` extends `A1771AnkerDevice` through a mixin (class header, `a1790_anker_device.dart` line 8). Asm-traced for the parsers; upstream-confirmed for the message id.

### Setters 0078, 005f, 0060, 0091

#### Purpose
Writes the third-party ATS (generator) parameters, switches an expansion battery or its light, and sets the locale of an F3800.

#### Upstream name
No upstream constant for these four opcodes (`mqttmap.py` has no `"0078"`, `"005f"`, `"0060"` or `"0091"` entry in a PPS block); `0079` is `CMD_PORT_MEMORY_SWITCH` upstream, listed for completeness.

#### Command code
Hex strings are pool lists of `charging/ble/device/A1790/a1790_device_controller.dart` (never halved). Asm-traced for the opcodes and tag keys.

#### Direction
app→device. Tag: asm-traced.

#### Topic pattern
[envelope.md](envelope.md#topics): `cmd/anker_power/A1790/<sn>/req`.

#### Payload fields
Tag keys are halved Smi immediates (324 is `a2`); widths are the `intToList` variants the functions call (`intToList2` for two bytes, `intToList3` for three).

#### Known unknowns
- The meaning of the four `setThirdATSData` values (generator parameters per the old doc; the asm shows widths only).
- Which argument of `setBMSSubBatteryPowerSwitch` and `setBMSSubBatteryLightSwitch` is the battery id and which the switch value: the asm has no parameter names, and the old doc's labels (`a2` battery id, `a3` switch) do not fit the widths found (`a3` is a string, `a2` and `a4` are 1-byte values). — traced 2026-10-20: a1790_device_controller.dart @0x2fd7ec4 and @0x2fd88a4.

`[0, 0x61]` is not referenced by `setBMSSubBatteryLightSwitch` (both its send calls use `[0, 0x60]`, @0x2fd8974 and @0x2fd899c); the only use in the A1790 controller is `getAllBmsSubBatteryInfo` @0x33d47e8 (pool reference @0x33d4888, a `formatCommand` call), and in the opcode map of [iot.md](iot.md#frame-decode-and-opcode-dispatch) `0061` is `getAllBMSSubBatteryInfoReq` (index 0x53, shadowed by `setA17b1CommandReq`), so it is the request that asks for the expansion battery data of the previous section.
