# A1340 MQTT commands (portable power bank)

Portable power bank A1340: the per-port parser and the device-level debug labels. The envelope, topics, frame layout and data type codes are owned by [envelope.md](envelope.md).

Evidence rows are written `audit row N` and refer to [../docs/audit/BLE_COMMAND_MAP.md](../docs/audit/BLE_COMMAND_MAP.md); `file.dart @0xADDR` is 3.24.3 asm. Tag keys are halved Smi immediates (per the Smi rule in [../METHODOLOGY.md](../METHODOLOGY.md#smi-rule-reading-numbers-from-blutter-output)). The header tag is `string-only` because the device-level labels are debug strings. A17D0 (generator input adapter) was found in the A17B1 parser; the audit rows treat it as prose (row 352) and it has no page here.

## Commands

### parseUploadChargePortInfo (per-port tags)

#### Purpose
Reads the per-port values (status, voltage, current, power, repeat) that a portable power bank A1340 uploads for its charge ports.

#### Upstream name
none: upstream has no `A1340` entry (`mqttmap.py`, `apitypes.py`).

#### Command code
No command code. `A1340DeviceCommands.parseUploadChargePortInfo` @0x3b92108 (size 0x518; `charging/ble/device/A1340/a1340_device_commands.dart`); the same file has `parseAllChargePortInfo` @0x3b929d0, `parseChargePortInfo` @0x3b92df4, `parseDeviceAllInfo` @0x3b96028 (size 0x1004) and `parsePortDataCurveInfo` @0x33e705c (function start and size from the asm header). Asm-traced for the tag set; the labels are string-only.

#### Direction
device→app. Tag: asm-traced.

#### Topic pattern
Not applicable: the audit does not bind the parser to an MQTT topic.

#### Payload fields
The old doc listed five fields for four ports (USB-C1, USB-C2, USB-A, DC/P). The audit confirms only that `parseUploadChargePortInfo` reads the tags a2 to aa, with a6 read twice (audit row 351); the pairing of tags to port and field is not traced. The old doc scales (voltage "x0.1 V?", current "x0.01 A?") are UNVERIFIABLE (audit row 650): the file contains `double(0.01)` constants but the binding to the voltage and current fields is not read.

#### Related API endpoint
none (MQTT only).

#### Since/changed
The tag set a2 to aa exists in 3.24.3 (audit row 351). The asm file has 9654 lines in 3.24.3 and 10550 lines in 3.18.0; the old doc figure of 10841 lines (audit row 350) is a size remark of some other build and not a protocol fact.

#### Known unknowns
- The pairing of the tags a2 to aa with ports and fields (status, voltage, current, power, repeat): not traced.
- The scale of voltage and current (audit row 650, UNVERIFIABLE): only `double(0.01)` constants were seen.
- Which transport and message id feed the parser (no upstream entry, no audit row).
- The old doc lists a per-port protocol field (`chargeProtocol`); no audit row covers it.
