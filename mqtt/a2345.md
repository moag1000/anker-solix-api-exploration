# A2345 MQTT commands (250 W Prime Charger)

250 W Prime Charger (A2345): the status parser (`parseDeviceAllInfo`), the per-port structure (OutputPortInfo, `parseChargePortInfo`) and the setters. The 240 W Charging Station (A91B2) has its own page: [a91b2.md](a91b2.md). The envelope, topics, frame layout and data type codes are owned by [envelope.md](envelope.md). The structure rows 91-97 (OutputPortInfo) are owned here; rows 89-90 (SubBatteryInfo) are on [a1790.md](a1790.md).

Evidence rows are written `audit row N` and refer to [../docs/audit/BLE_COMMAND_MAP.md](../docs/audit/BLE_COMMAND_MAP.md); `file.dart @0xADDR` is 3.24.3 asm. Tag keys are halved Smi immediates (per the Smi rule in [../METHODOLOGY.md](../METHODOLOGY.md#smi-rule-reading-numbers-from-blutter-output)). Names are upstream's (`api/mqttmap.py`); a name of ours is marked `(no upstream name)`.

## Commands

### parseDeviceAllInfo (status tags, upstream message 0a00)

#### Purpose
Decodes the full status of a 250 W Prime Charger (A2345): six port blocks, port switches, settings and the version.

#### Upstream name
The nearest upstream map is the `"0a00"` message `_A2345_0a00` (`mqttmap.py` lines 3014-3196; sent on the status request `"0200"`, line 5447) and the per-second `"0303"` message `_A2345_0303` (lines 2870-3013, `state_info`), both upstream-confirmed. The old doc called this the "0405 status" of A2345; upstream has no `"0405"` entry for A2345. The 3.24.3 controller binds the parser to the opcode bytes `0a 00` and the per-second port message to `03 03` (see Command code), which is upstream's reading, so the old doc's `0405` is not what the app code uses (app side; the id on the wire is device test row 94).

#### Command code
Message id (app side, re-read 2026-10): in the A2345 controller `OPCODE_KEY == [0xa, 0]` (`listEquals` @0x3b28b18, log `getAllDeviceInfoRes` @0x3b28b24) calls `parseDeviceAllInfo` @0x3b28c04, and `OPCODE_KEY == [0x3, 0x3]` (@0x3b28fe0) calls `parseUploadDCPortState` @0x3b2902c; the controller has no `[0x4, 0x5]` compare. `OPCODE_KEY` is the two opcode bytes with element 0 masked by `& 0xf` ([iot.md](iot.md#frame-decode-and-opcode-dispatch)), so the ids are 0a00 and 0303. `A2345DeviceCommands.parseDeviceAllInfo` @0x3b2ff2c (size 0x1990; `charging/ble/device/A2345/a2345_device_commands.dart`). It reads 30 `indexString` arguments (a2 to b5: 20, b7 to bf: 9, and `fe`); the old doc said 28 (audit row 329, WRONG). Asm-traced for the tag set.

#### Direction
device→app. Tag: asm-traced.

#### Topic pattern
[envelope.md](envelope.md#topics): `dt/anker_power/A2345/<sn>/state_info` for `0303`, and the param/state topic of the message that carries the tags is not bound by an audit row.

#### Payload fields
Rows are the tags read as `indexString` arguments (hex number equals the decimal argument); the audit checked tag numbers only (rows 330-340). The tag-read addresses are from the same asm function (new read, tag numbers only; `bc` to `bf` and `fe` appear after `bb` in the read order). Upstream names exist only for `a2`, `a4` to `ae` and `fe`; `a3`, `af`, `b0` to `b5` and `b7` to `bf` have none. Upstream describes `a4` to `a9` as six port blocks; the old doc listed only `a4` to `a6` as port blocks and called `a7` to `ab` plain ints, and the asm calls `parseChargePortInfo` six times and `parseChargePortACInfo` five times inside this function (@0x3b3024c, @0x3b302b8, @0x3b30324, @0x3b30390, @0x3b303fc, @0x3b30468 and @0x3b304d4, @0x3b30540, @0x3b305ac, @0x3b30618, @0x3b30784). Re-read 2026-10: the six `parseChargePortInfo` calls take the entries of `a4` to `a9` in order and the five `parseChargePortACInfo` calls those of `aa` to `ae` (key loads `ldur x2,[fp,#-0x30]` to `[fp,#-0x58]` @0x3b30218, @0x3b30284, @0x3b302f0, @0x3b3035c, @0x3b303c8, @0x3b30434 and `[fp,#-0x60]` to `[fp,#-0x80]` @0x3b304a0, @0x3b3050c, @0x3b30578, @0x3b305e4, @0x3b30750; the slots are filled in read order from `a2` at `[fp,#-0x20]`), which matches upstream's six port blocks and not the old doc's `a7` to `ab` ints.

### OutputPortInfo (parseChargePortInfo, per port)

#### Purpose
Decodes one USB port block of the A2345: index, voltage, current, power and optional status and temperature.

#### Upstream name
Upstream byte map of each port block: `status` ("00"), `voltage` ("01"), `current` ("03"), `power` ("05") in `_A2345_0303` and `_A2345_0a00` (`mqttmap.py` lines 2870-3013 and 3014-3196), upstream-confirmed. The app class `OutputPortInfo` has no upstream name.

#### Command code
No command code. `A2345DeviceCommands.parseChargePortInfo` @0x3b2eb9c (size 0x340). Shorter payloads than 7 bytes are rejected (`cmp x1,#7`, `b.ge` @0x3b2ec30; audit row 91). Asm-traced.

#### Direction
device→app. Tag: asm-traced.

#### Topic pattern
Not applicable: the port block is a sub-structure of the status message (see the previous section).

#### Payload fields
Indexes are list byte positions; the audit corrected the old doc: voltage, current and power are 2 bytes each, not 4, and the status and temperature positions are [7] and [8] (audit rows 93-97). The upstream byte keys "01", "03", "05" agree with the 2-byte windows.

#### Related API endpoint
none (MQTT only).

#### Since/changed
The windows were confirmed in 3.24.3 (audit rows 91-97). No 3.18.0 difference is recorded for this sub-parser.

#### Known unknowns
- The units of voltage, current and power: upstream scales them (0.001, 0.001, 0.01) but the asm does not show a unit.
- Why the status byte at [7] is read only for payloads longer than 8 bytes while the minimum payload is 7 bytes (audit row 96): the compares are `cmp x1,#7` (minimum, @0x3b2ec30), `cmp x1,#8` (@0x3b2edb8, guards [7]) and `cmp x1,#9` (@0x3b2ee74, guards [9]) after `LoadInt32Instr` (64-bit, real lengths), so a block of exactly 8 bytes leaves [7] unread and a block of 9 bytes leaves [9] unread; the reason is a developer decision. — traced 2026-10-20.
- The old doc names `chargeProtocol`, `maxChargePower`, `protocolCurrent`, `protocolVoltage` as extra per-port info of the A2345. New read 2026-10-20: none of the four names occurs in any A2345 or A91B2 file under `charging/ble/device` (`grep -c` 0 in the `commands`, `controller`, `device` and `feature` files of both); the A2345 `OutputPortInfo` constructor takes no named arguments in `parseChargePortInfo` @0x3b2eb9c (`OutputPortInfo()` @0x3b2ec5c); the four names are the named arguments of the A1340 `ChargePortInfo` ([a1340.md](a1340.md#parsechargeportinfo-block-shapes)) and appear in `scp_enums.dart` and the two custom-charging edit pages (`chargeProtocolConfig`). The 2026-10 read therefore does not support them as A2345 parser fields.

#### Device-tested by
none.

### Setters (A2345 controller)

Sets the charging mode, the DC port timer and relay, the UFCS switch, the button rotate direction and the screen saver of a 250 W Prime Charger.

#### Upstream name
Opcodes read from the pool lists of the app functions (table below); upstream has the generic commands `"0200"` status request, `"0207"` USB port switch (a2 port selector, a3 on/off) and `"020b"` realtime trigger for A2345 (`mqttmap.py` lines 5447, 5448 and 5514), upstream-confirmed. Of the app functions below, `setDCRelaySwitch` (`0207`) has the id upstream names the USB port switch; the others (`0205`, `0206`, `0209`, `020e`, `0215`) have no upstream binding in the cited lines.

#### Command code

#### Direction

#### Topic pattern
[envelope.md](envelope.md#topics): `cmd/anker_power/A2345/<sn>/req`.

#### Payload fields
