# A5140, A5141, A5143 (MI60 and MI80 microinverters) BLE

The MI60 and MI80 microinverters (A5140, A5141, A5143). This page owns the BLE-specific facts of the product; the command payloads (opcodes, TLV tags, scales) are owned by no MQTT page (the product is not covered by [../mqtt/README.md](../mqtt/README.md)); the BLE opcode lists below are the only command facts this repository has for it. The frame, fragmentation and encryption are on [protocol.md](protocol.md), the negotiation on [handshake.md](handshake.md).

Evidence is the asm of 3.24.3 (`file.dart @0xADDR`, relative to `charging/ble/device/` unless a path is given). Pool lists such as `[0, 0x5e]` are real values. A row that says `no` in the column `on the MQTT page` means the opcode is not mentioned on the linked page; it can still be a command that also goes over MQTT.

Notes on this product:

- `A5140AnkerDevice` mixes in `PpsDeviceFeature` only (no `ZXBleFeature`); `A5141AnkerDevice` and `A5143AnkerDevice` extend it, and `A5140Commands` is the parser (`A5140/a1780_commands.dart`, same file name as the A1780 parser). The factory gives A5141 and A5143 the `A5140DeviceController` (`device_factory_impl.dart @0x240e79c`, `@0x240e810`).
- A5140 and A5141 have no GATT profile in the product table (the product name fills every UUID field); only A5143 has UUIDs (the `effe` group). `AnkerDevice.updateStatus` ends all three in `disconnect` (`anker_device.dart @0x220626c`).
- The A5140 DeviceStatus model is on [../models/pps.md](../models/pps.md). There is no MQTT page for these products.
- Session setup, app side: `A5140AnkerDevice` and its subclasses `A5141AnkerDevice` and `A5143AnkerDevice` (class ids 8453 to 8455) have no `ZXBleFeature` in their `extends` lines; their class ids are outside the ids that `ZXBleConfer.sendConnectCommand` accepts, so the Dart conferers send no start-connect request for them ([handshake.md](handshake.md#which-implementation-runs-for-a-product)). `A5140`, `A5141` and `A5143` are not registered SDK product codes, so `BleHandler` picks `BleHandlerImpl1`; `_authDevice` still calls `startZXBleConfer`. The legacy connect path (`SimpleBleConnector._connectLegacyDevice`) is not linked from this class: `SimpleBleConnector.connect` has a single caller in the asm, in the A7320 unbind flow ([protocol.md](protocol.md#stacks-and-send-routing)). The connect call for this product: no home page for these codes calls it; the generic callers are `charging/impl/device_serviceImpl.dart @0x27f1560` and `ui/page/device/main/station_device_home/device_main_page/device_main_logic.dart @0x2446d44`. No negotiation step for this class is visible in the asm.

## Commands

### Device-class methods

#### Purpose

Records that this device class has no ZX handshake method; the session setup of the product is not the ZX negotiation of [handshake.md](handshake.md).

#### Upstream name

none for the sequence; the opcode names are the app's `ZXOpcodeType` members (no upstream name).

#### Opcode

No pool opcode list in `a5143_anker_device.dart`, `a5141_anker_device.dart`, `a5140_anker_device.dart`: the class defines no opcode methods and does not mix in `ZXBleFeature`.

#### Direction

both: requests go app to device, the responses (`08xx` in the common map, [handshake.md](handshake.md#opcode-pairs)) come back device to app.

#### Packet framing

[protocol.md](protocol.md#frame-on-ble); the handshake frames carry the flag bits of [protocol.md](protocol.md#opcode-byte-0-flags).

#### Handshake prerequisite

The rows of group `handshake` are the handshake. Which conferer runs (`SecureEcdhConfer`, `EcdhConfer` or `AesConferV1`) is chosen from the capability response, not from the product: [handshake.md](handshake.md#capability-negotiation-response). The other rows are ordinary commands that need a completed handshake for encrypted frames.

#### TLV tags

The handshake payloads are positional bytes or single tags and are not per-product; they are described in [handshake.md](handshake.md#capability-negotiation-response) and [handshake.md](handshake.md#the-three-conferers). The payloads of the WiFi, OTA and status-request rows were not decoded for this page.

#### Example

none: no capture of a handshake exists in this repository.

#### Related API endpoint

none: the handshake has no MQTT twin and the product has no MQTT page.

#### Since/changed

3.18.0: the same device-class files. 3.24.3: the opcode set of the device-class file(s) is unchanged; the `ProductModel` of A5140, A5141, A5143 existed in 3.18.0 (see [protocol.md](protocol.md#since-3180)).

#### Known unknowns

none (app side); device side: device test row 110 ([backlog](../docs/DEVICE_TEST_BACKLOG.md)).

BLE is unavailable while the device is on WiFi; see `ble/protocol.md` (community finding, see protocol.md; not asm-traced).

#### Device-tested by

none.
