# Information Architecture and Fact Ownership

This page defines where every kind of fact lives in the rebuilt repository and how the existing files migrate there. The rule is single source: a fact lives on exactly one owner page, and every other page links to it. Tags, the Smi rule and the page header format are defined in [../METHODOLOGY.md](../METHODOLOGY.md); the reader paths that depend on this layout are in [PERSONAS.md](PERSONAS.md).

## Ownership rule

Payload facts live in `api/<service>/<endpoint>.md`; `devices/` and `flows/` link, they never copy.

| Fact type | Owner page |
|---|---|
| Endpoint payload and parameters | `api/<service>/<endpoint>.md` |
| param_type and cmd values | `api/param_types.md` |
| Error codes | `api/errors.md` |
| Auth headers and login | `api/auth.md` |
| Payload encryption and encryption headers | `api/encryption.md` |
| How the direct SDK senders (command map, `AkNetwork.requestHttp`, `ScheduleNetwork`) build and send a request | `api/sdk_senders.md` |
| MQTT field maps | `mqtt/<pn>.md` |
| MQTT envelope | `mqtt/envelope.md` |
| BLE opcodes and TLV | `ble/<pn>.md` (handshake: `ble/handshake.md`; frame format: `ble/protocol.md`) |
| Model fields | `models/` |
| Enums and product codes | `reference/enums.md` |
| Business rules | `reference/business_rules.md` |
| Device to command matrix | `reference/command_matrix.md` |
| Validation (GET to SET) | `reference/validation_model.md` |
| Flows | `flows/<name>.md` (links only, no payload copies) |
| Devices | `devices/<pn>.md` (links and device-tested status only) |
| Machine-readable data | `data/*.json` (generated by `tools/`) |

If a fact is needed on a non-owner page, link to the owner. When an owner page is corrected, grep for the old value across the repository before committing.

## Naming conventions

- File names are lowercase with underscores.
- Endpoint pages are named exactly after the last URL segment, for example `set_site_device_param.md`.
- PN pages use the lowercase product number, for example `a17c5.md`.
- Service directories are named exactly after the URL prefix, for example `charging_hes_svc/`.
- Endpoint page path: `api/<service>/<intermediate segments>/<last_segment>.md`. The `v1` segment (the default API version) is dropped; any other version segment (`v2`, `v3`, ...) is kept as a path segment. Example: `/power_service/v1/site/get_power_limit` is `api/power_service/site/get_power_limit.md`, `/power_service/v2/device/energy_options` is `api/power_service/v2/device/energy_options.md`. A URL that starts with a version segment (`/v2/anka/...`) follows the URL-prefix rule: `api/v2/anka/...`. `tools/render_pages.py` (`endpoint_path`) implements this and refuses to render two URLs to one path.
- Upstream names (apitypes.py keys, mqttmap names) win over ours.

## Migration map

One row per tracked Markdown file outside `docs/` (root docs, `devices/`, `endpoints/`, the legacy group pages of `models/`, `patches/README.md`). The Status column is derived from the files on disk by `tools/readme_stats.py` (run it, do not edit the column by hand). Legend: `done` = every owner target in the row exists (`done (skeleton pages)` when every such page still has a TODO purpose, so the owner exists but carries no content yet); `partial` = some exist; `pending` = none exists; `kept` = the file stays its own owner. A target with `<...>` or a bare directory only proves that something exists, so such a row is at most `partial`, except wildcards under `api/` (every inventory URL has a page there, see the generated coverage in the [README](../README.md#statistics-and-coverage)). An in-place rebuild (the target is the old file itself) counts as not yet done. `done` means an owner page exists; it does not mean the old page is bannered or deleted (that is Task 4.9).
