# A17C5 MQTT commands (differences from A17C1)

Solarbank 3 (A17C5) uses the same app controller and the same status parser family as the Solarbank 2 (A17C1). This page states only the differences and links the owner pages for everything shared: SET opcodes and their tags are on [a17c1.md](a17c1.md), the 0405 field handling on [a17c1_status.md](a17c1_status.md), the frame and topics on [envelope.md](envelope.md).

Evidence rows are written `audit row N` and refer to [../docs/audit/BLE_COMMAND_MAP.md](../docs/audit/BLE_COMMAND_MAP.md) (rows 637-648 are the A17C5 section); `file.dart @0xADDR` is 3.24.3 asm. Upstream names win: A17C5 names are from `_A17C5_0405` (`api/mqttmap.py` lines 2138-2212) and A17C1 names from `_A17C1_0405` (lines 1796-1863). A device-level product page exists at [../devices/a17c5.md](../devices/a17c5.md).

#### Related API endpoint
Site-level equivalents: [get_site_device_param](../api/power_service/site/get_site_device_param.md).

#### Since/changed
No A17C5 versus A17C1 difference changed between 3.18.0 and 3.24.3 in the tag sets (the two parsers list identical `indexString` arguments in both versions, audit rows 637-643). Store offsets moved in the shared family parsers as described for A17C1 (for example the temperature store 0x307 to 0x313 in `a17c5_device_commands.dart` @0x4861520, audit row 58).

#### Known unknowns
- Whether the A17C5 parser divides power or energy tags: upstream defines no factor for A17C5 power tags (`mqttmap.py` lines 2148-2155) while A17C1 divides `ab`, `ac` by 10; only the A17C1 divisors are audited (audit rows 56, 182).
- The old doc placed `temperature` at `aa` for A17C5; upstream names `a5`. The audit shows the A17C5 parser reads `aa` (audit row 640) but not which field it feeds.
- Tags `bc`, `c3`, `c4`, `c5` and the bit meanings of `ba` (upstream: light mode, LED switch, AC socket switch, temperature unit as bits of byte 00, `mqttmap.py` lines 2164-2185) were not audited per bit.

#### Device-tested by
none recorded in this repo for the A17C5 status message.

### Shared SET opcodes 005e 0067 0073 0080 009a

#### Purpose
The opcodes upstream binds to the A17C5 map, and which of them the shared controller builds.

#### Upstream name
`CMD_SB_USAGE_MODE` (005e, line 5167, description only), `CMD_SB_MIN_SOC` (0067, line 5168), `CMD_SB_AC_SOCKET_SWITCH` (0073, line 5178), the `0080` group `sb_max_load`, `sb_disable_grid_export_switch`, `sb_pv_limit_select`, `sb_ac_input_limit` (line 5179), `CMD_SB_DEVICE_TIMEOUT` (009a, line 5206); all in `mqttmap.py`, upstream-confirmed.

#### Command code
`"005e"`, `"0067"`, `"0073"`, `"0080"`, `"009a"`: pool lists `[0, 0x5e]`, `[0, 0x67]`, `[0, 0x73]`, `[0, 0x80]`, `[0, 0x9a]` exist and the builders are in `a17c1_device_controller.dart`, which the A17C5 reuses (audit rows 644-645). Asm-traced.

#### Direction
app→device. Tag: asm-traced.

#### Topic pattern
[envelope.md](envelope.md#topics): `cmd/anker_power/A17C5/<sn>/req`.

#### Payload fields
| tag | name | type | unit/scale | required | source |
|---|---|---|---|---|---|
| `a7` of 0080 | `set_sb_pv_limit_select` | 2 bytes | 2000 or 3600 W (upstream) | no | audit row 645; setDevicePowerLimit @0x227704c; upstream-confirmed (`mqttcmdmap.py` line 764) |
| `a8` of 0080 | `set_ac_input_limit` | 2 bytes | 0 to 1200 W, step 100 (upstream) | no | audit row 645; setDevicePowerLimit @0x2277134; upstream-confirmed (`mqttcmdmap.py` line 775) |
| `a4` of 0080 | `set_max_load_a4?` | 2 bytes | 0 observed (upstream) | no | audit row 644; setDevicePowerLimit builder writes `a2` to `a8`; upstream-confirmed (`mqttmap.py` line 5196) |
| `a2` of 0067 | `set_min_soc` | 1 byte | 5 or 10 percent (upstream) | yes | audit row 645; setSoc; upstream-confirmed (`mqttcmdmap.py` line 632) |
| `a2` of 009a | `set_device_timeout_min` | 1 byte | raw value; the app does not multiply by 30 | yes | audit rows 180, 228; getSleepTimeInt @0x4864804 reads tag 0xD4 with `listToInt` and no division; upstream-confirmed (`mqttcmdmap.py` line 820) |

The opcodes and tags exist in the shared A17C1 controller, so they are not SB3-exclusive in code (audit row 645); the 2000/3600 W and 0 to 1200 W values are upstream constants. The A17C1 `0067` builder has a three-tag form (`a2`, `a3`, `a4`) and a four-tag form (`a2`, `a5`, `a6`, `a7`); which form the A17C5 uses is not in the audit.

#### Example
none; see [a17c1.md](a17c1.md) for the frame of each opcode.

#### Related API endpoint
[set_site_device_param](../api/power_service/site/set_site_device_param.md).

#### Since/changed
No change recorded by the audit.

#### Known unknowns
- Which `0067` form (three-tag or four-tag) is sent for A17C5.
- Whether `005e` is sent directly (upstream says it is cloud-driven and uses the description only).

#### Device-tested by
none recorded for A17C5.

### 0085 and multi-system messages 0420 0421 0428

#### Purpose
The third-party PV switch and the dock multi-system messages that upstream lists for A17C5.

#### Upstream name
`CMD_SB_3RD_PARTY_PV_SWITCH` (`"0085"`, `mqttmap.py` line 5205, "cloud driven"); `_DOCK_0420`, `_DOCK_0421`, `_DOCK_0428`, `_DOCK_0500` (lines 5218-5224), upstream-confirmed.

#### Command code

#### Direction
`0085` app→device (cloud-driven per upstream); `0420`, `0421`, `0428` device→app (upstream `mqttmap.py`).
