# A5101 MQTT and data-code reference

X1 HES (A5101; A5102 and A5103 share the upstream map): the JSON status the app receives over MQTT, the BLE data-code maps with the corrected code pairing, and the two A5101 opcodes the audit confirms. The envelope, topics and frame layout are owned by [envelope.md](envelope.md) and not repeated here. The BLE data codes are documented here because the same enum names the MQTT-side values; BLE is a local protocol and is never a live fallback for the cloud connection.

Evidence rows are written `audit row N` and refer to [../docs/audit/BLE_COMMAND_MAP.md](../docs/audit/BLE_COMMAND_MAP.md); `file.dart @0xADDR` is 3.24.3 asm. Code files: `charging/ble/device/A5101/a5101_commands.dart` (`setDataCodeMap` @0x3b88c14 size 0x1e70, `getDataCodeMap` @0x3b8aa84 size 0x1c24) and `a5101_device_controller.dart`. Pool lists such as `[0x9, 0xee]` are real values (untagged); a map key is the hex string of such a list and the value is the `A5101DataCodeType` enum instance stored right after it (audit rows 201-215 explain the pairing). Names are upstream's (`api/mqttmap.py`); a name of ours is marked `(no upstream name)`. Audit rows 189-198 (FeatureSwitch, `A5101DeviceCommandModel` with class size 0x54, which is 19 slots, and example payloads) describe API models and belong to `models/hes.md`; they are not repeated here.

### JSON status (trans payload)

#### Purpose
Periodic system status of the X1: energy flow, daily and total energies, battery pack data.

#### Upstream name
`_X1_JSON`, bound as `"json"` for A5101, A5102 and A5103 (`mqttmap.py` lines 3945-4013, 5832-5846), upstream-confirmed.

### Data code maps (setDataCodeMap and getDataCodeMap)

#### Purpose
The BLE write map and read map that bind a 2-byte data code to an `A5101DataCodeType` enum member.

#### Upstream name
none (the A5101 BLE command set is not mapped upstream; `A5101DataCodeType` is the app's enum).

Data codes, not opcodes: the enum has 133 members (pool objects `Obj!A5101DataCodeType`, audit row 199; the old doc said 131). Both maps are built at @0x3b88c14 and @0x3b8aa84; every one of the 133 members appears in at least one map (audit row 216). Asm-traced.

#### Direction

#### Topic pattern
none: BLE only, not an MQTT topic.

### Work mode numbers (cloud strategy `mode` and Bluetooth shift mode)

#### Purpose
The mode numbers the system policy page sends when the user changes the work mode of an X1 HES: as `mode` in the `electricity_strategy` of the cloud `device_command`, or as the value of the Bluetooth write `setShiftMode`. The sequence is [../flows/a5101_work_mode_change.md](../flows/a5101_work_mode_change.md).

#### Upstream name
none (our names from the handler and function names of the app; `(no upstream name)`).

#### Command code
No opcode: `SystemPolicyLogic::sendDeviceCommandOfMode` (`system_policy_logic.dart @0x249f5a0`) takes the number as an unboxed int, so the register values are real. Asm-traced.

#### Direction
app→cloud (`device_command`) or app→device (Bluetooth `setShiftMode`, code pair `[0, 0]` through `setAtt`, `a5101_ble_logic.dart @0x249f7d8`, `@0x249f844`).

#### Topic pattern
none: cloud request body or Bluetooth write, not an MQTT topic.

#### Payload fields
| tag | name | type | unit/scale | required | source |
|---|---|---|---|---|---|
| `mode` 0 | `selfPowered` card | int | work mode number | yes | `system_policy_view.dart @0x3ec9dc0` |
| `mode` 1 | time-of-use (`sendDeviceCommandOfTou`, `SmartShiftMode` card, text `timeOfUse`) | int | work mode number | yes | `system_policy_logic.dart @0x249f50c`, `@0x3ec99c4` |
| `mode` 2 | `offGridPowerConsumption` card | int | work mode number | yes | `system_policy_view.dart @0x3ec477c` |
| `mode` 11 | `billSavingOptimization` card | int | work mode number | yes | `system_policy_view.dart @0x3ec3fbc` |
| `mode` 16 | time slot (`sendDeviceCommandOfTimeslot`, text `timeSlot`) | int | work mode number | yes | `system_policy_logic.dart @0x3ec7f40`, `@0x3ec7e28` |
| `mode` 20 | AI EMS (`sendDeviceCommandOfAIEmsMode`) | int | work mode number | yes | `system_policy_logic.dart @0x3eca5e8` |

The names come from the handler log texts and function names; which firmware mode each number selects is the device's business. The old doc named 16 as AI EMS (audit row 59); the function names show 16 is the time-slot mode and 20 the AI EMS mode.
