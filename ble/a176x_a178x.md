# A1763, A1765, A1782, A1783, A1785 (kit-driven portable power stations) BLE

The product codes of the A176X and A178X range that have no device class in the app: A1763 (SOLIX C1000 Gen 2), A1765 (SOLIX C1000X Gen 2), A1782 (SOLIX F3000), A1783 (SOLIX C2000 Gen 2) and A1785 (SOLIX C2000X Gen 2). The file name keeps the grouping of the 3.18.0 archive section ("A172X / A176X / A178X"); the other members of that range have their own pages: A1761 and A1762 on [a1753.md](a1753.md), A1780 on [a1780.md](a1780.md), A1780P on [a1780p.md](a1780p.md), A1781 on [a1781.md](a1781.md), A1770 and A1771 on [a1770.md](a1770.md) and [a1771.md](a1771.md). The five codes here are built by the generic fallback (`IotAnkerDevice` and `IotDeviceController`, see [../mqtt/iot.md](../mqtt/iot.md#fallback-handler-iotdevicecontroller)); their commands are named kit actions of the `A1782` module, not opcodes. The frame, fragmentation and encryption are on [protocol.md](protocol.md), the negotiation on [handshake.md](handshake.md).

Evidence is the asm of 3.24.3 (`file.dart @0xADDR`, relative to `charging/` unless a path is given). Opcodes quoted from other pages keep the sites printed there.

## Commands

### Kit actions of the A1782 module (no opcode)

#### Purpose

Lists the eight kit-builder methods of `pps_command.dart` (the A1782 module) and the action or property literal each one sends through `akiot.device.invoke_action`.

#### Upstream name

none (the app's method names are used; the upstream names of the two Gen 2 codes are in the table above).

#### Opcode

Tag: asm-traced.

No ZX opcode exists on the Dart side for these codes. The module's command file is `ak_iot_kit/business/A1782/command/pps_command.dart`; every method builds a map and hands it to `AKIoTKitManagerImpl.handle`, the channel string is `akiot.device.invoke_action` ([../reference/iot_kit_channels.md](../reference/iot_kit_channels.md#channel-inventory)). The pool strings of each function, in code order, are listed in the last column; the first group are the named arguments, the second the map keys.

| method | action or property literal | pool strings in the function | site |
|---|---|---|---|
| `setCycleChargingPower` | `action_set_cycle_charging_power` | `cycleChargingPower`, `deviceSn`, `bleMac`, `id` | pps_command.dart @0x26d1c64 |
| `readDeviceCurrentWifi` | `prop_read_device_current_wifi` | `deviceSn`, `bleMac`, `id` | pps_command.dart @0x27b0584 |
| `startSelfCheck` | `action_start_self_check` | `selfCheckState`, `selfCheckType`, `deviceSn`, `bleMac`, `id` | pps_command.dart @0x2acef40 |
| `setACParams` | `action_set_ac_params` | `acEnergySavingSwitch`, `acFrequency`, `acInputDisableSwitch`, `acInputStatus`, `acRechargePower`, `acTimerValue`, `b6RechargePower`, `d1RechargePower`, `superFastChargeStatus`; map keys the same names with `a17D1RechargePower` and `a17B6RechargePower` | pps_command.dart @0x2cdaf18 |

| `getDeviceOtaStatus` | `check_device_ota_status` | `deviceSn`, `bleMac`, `id` | pps_command.dart @0x357c6dc |

All eight carry the keys `deviceSn`, `bleMac` and `id` (the actions that take parameters also the key `param`); which key holds which value was not decoded. The keys `a17D1RechargePower` and `a17B6RechargePower` carry the accessory codes A17D1 and A17B6 in their names; A17D4 and A17B6 occur as sub-package keys (`"A1782_A17D4"`, `"A1782_A17B6"`) in `ui/page/device/a1782/utils/generate_subpackage_json.dart` (`addAdditionalSubPackageFunc` @0x4151438) and in the OTA parser (see [BLE profile](#ble-profile)).

#### Direction

app to kit (app side: the Dart layer hands the map to the native IoT kit); the app passes both the cloud serial (`deviceSn`) and the BLE address (`bleMac`). Which transport the kit uses is below the Dart layer and is not shown by the asm.

#### Packet framing

none on the Dart side; the kit frames the data ([protocol.md](protocol.md#frame-on-ble) describes the ZX frame of the opcode-based products).

#### Handshake prerequisite

Not visible in the Dart code of these methods; the kit negotiates below the Dart layer ([handshake.md](handshake.md)).

#### TLV tags

none decoded: the app names no tag for these actions. The MQTT page of the generic decoder is [../mqtt/iot.md](../mqtt/iot.md); no MQTT page covers these codes.

#### Example

none: no capture exists in this repository.

#### Related API endpoint

[../reference/iot_kit_channels.md](../reference/iot_kit_channels.md), [../api/sdk_senders.md](../api/sdk_senders.md), [../reference/enums.md](../reference/enums.md) (product table).

#### Since/changed

3.18.0: the archive section did not describe these codes. 3.24.3: the eight methods above.

#### Known unknowns

- Whether the kit sends an action over BLE, MQTT or the cloud, and the frame of a BLE write.
- Which of the keys `deviceSn`, `bleMac`, `id` and `param` holds the action literal and which the parameter map.
- Value ranges of the parameters (the builders pass the arguments unchanged; no range check is in these functions).
- Why A1765 and A1785 have no `ProductModel`.

BLE is unavailable while the device is on WiFi; see `ble/protocol.md` (community finding, see protocol.md; not asm-traced).

#### Device-tested by

none.
