# A17C1 MQTT commands

Solarbank 2 Pro/Plus (A17C1) over MQTT: the SET opcodes the 3.24.3 app builds for this product. The 0405 status message and the status/realtime requests are on [a17c1_status.md](a17c1_status.md) (split off to stay under 600 lines). The A17C3 and A17C2 products share the controller functions; A17C5 (Solarbank 3) differences are on [a17c5.md](a17c5.md). The envelope, topics, frame layout and the data type codes are owned by [envelope.md](envelope.md) and not repeated here.

Evidence rows are written `audit row N` and refer to [../docs/audit/BLE_COMMAND_MAP.md](../docs/audit/BLE_COMMAND_MAP.md); `file.dart @0xADDR` is 3.24.3 asm. Opcodes are the hex strings of the Dart source (pool lists `[0, 0x5e]` are the same two bytes, never halved); field keys come from `r2 = 324` style immediates that are halved (324 is tag `a2`), per the Smi rule in [../METHODOLOGY.md](../METHODOLOGY.md#smi-rule-reading-numbers-from-blutter-output). Names are upstream's (`api/mqttmap.py`, `api/mqttcmdmap.py`); a name of ours is marked `(no upstream name)`. All SET commands are sent as `normalCommand` through the generic frame with an `FE` timestamp trailer unless the command says it writes the `FD` CRC trailer. Controller file for every SET row: `charging/ble/device/A17C1/a17c1_device_controller.dart`.

### 0050 setTempUnit

#### Purpose
Switches the temperature unit shown by the device between Celsius and Fahrenheit.

#### Upstream name
`CMD_TEMP_UNIT` (`temp_unit_switch`, `mqttcmdmap.py` line 250; `mqttmap.py` line 4991), upstream-confirmed.

#### Command code
`"0050"`, pool list `[0, 0x50]`, setTempUnit @0x3d98ffc (audit row 217). Asm-traced.

#### Direction
app→device. Tag: asm-traced.

#### Topic pattern
[envelope.md](envelope.md#topics): `cmd/anker_power/A17C1/<sn>/req`.

#### Payload fields
| tag | name | type | unit/scale | required | source |
|---|---|---|---|---|---|
| `a2` | `set_temp_unit_fahrenheit` | 1 byte | 0 Celsius, 1 Fahrenheit (upstream values) | yes | audit row 217; generic single-value frame key @0x22736f8 (raw 324); upstream-confirmed (`mqttcmdmap.py` line 253) |

#### Example
synthesized

```text
ff 09 <len> 03 00 0f 00 50 | a1 01 22 | a2 02 01 01 | fe 05 03 <ts> | xor
```

#### Related API endpoint
none (MQTT only).

#### Since/changed
The temperature value itself is stored at a moved offset (0x307 to 0x313), see [a17c1_status.md](a17c1_status.md#sincechanged).

#### Known unknowns
- The 0 and 1 meaning is upstream's; the setter forwards the UI index unboxed (audit row 169).

#### Device-tested by
A17C1 FW 1.0.6.10, mqtt_monitor ([../devices/solarbank.md](../devices/solarbank.md)); date and client version not recorded.


### 005e setBackPower, setTacticsTime, setPeakValley

#### Purpose
Three builders share the opcode: a timed backup window (usage mode), the time-slot schedule, and the peak-valley mode.

#### Upstream name
`CMD_SB_USAGE_MODE` (`sb_usage_mode`, `mqttcmdmap.py` line 838; bound for A17C5 at `mqttmap.py` line 5167; upstream notes it is cloud-driven and not meant to be sent), upstream-confirmed for the field names.

#### Command code
`"005e"`, pool list `[0, 0x5e]` at setBackPower @0x281a5bc and setTacticsTime @0x288b284 (audit row 165). Asm-traced.

#### Direction
app→device. Tag: asm-traced.

#### Topic pattern
[envelope.md](envelope.md#topics): `cmd/anker_power/A17C1/<sn>/req`.

#### Payload fields
setBackPower (audit row 218; keys halved from raw 324, 326, 328, 332, 334; value widths from `intToList` x3 and `intToList4` x3):

| tag | name | type | unit/scale | required | source |
|---|---|---|---|---|---|
| `a2` | `set_usage_mode` | 1 byte | mode number | yes | audit row 218; setBackPower @0x281a5e0; upstream-confirmed (`mqttcmdmap.py` line 847) |
| `a3` | `set_timestamp_a3_or_0?` | 1 byte | flag | yes | audit row 218; @0x281a610; upstream-confirmed (`mqttcmdmap.py` line 861) |
| `a4` | `set_backup_charge_switch` | 1 byte | switch | yes | audit row 218; @0x281a658; upstream-confirmed (`mqttcmdmap.py` line 865) |
| `a6` | `set_timestamp_backup_start` | 4 bytes | timestamp | yes | audit row 218; @0x281a698; upstream-confirmed (`mqttcmdmap.py` line 880) |
| `a7` | `set_timestamp_backup_end` | 4 bytes | timestamp | yes | audit row 218; @0x281a6d8; upstream-confirmed (`mqttcmdmap.py` line 940) |
| `fd` | (no upstream name for this use) | 4 bytes | CRC32 of the payload | yes | audit row 219; @0x281aa44..0x281aa94 (key raw 506) |

setPeakValley (audit row 221): `a2` mode and `a3` flag @0x428a888, @0x428a8c8, then the CRC32 under `fd` @0x428b058..0x428b0a8.

setTacticsTime (audit rows 84, 88, 220): 29 data tags `a2` to `be` (keys raw 324..380 halved; the array length raw 116 is 58 elements = 29 key/value pairs @0x288ac88) followed by the CRC32 under `fd` @0x288b238. The data tags are one mode tag plus seven slots of four tags; each slot is a `DischargeTimeModel` with four integer fields (class size 0x20): `startTime` 0x8, `endTime` 0xc, `power` 0x10, `chargingPercentage` 0x14 (audit rows 85-86, `pps_device_feature.dart` class header). The old doc said 14 slots and 30 tags plus a timestamp; both were raw Smi readings (audit rows 84, 88).

#### Example
synthesized. The CRC bytes are not computed.

```text
ff 09 <len> 03 00 0f 00 5e | a1 01 22 | a2 02 01 <mode> | a3 02 01 00 | a4 02 01 <0|1> | a6 05 03 <start> | a7 05 03 <end> | fd 05 03 <crc32> | xor
```

#### Related API endpoint
Schedule writes through the cloud: [set_site_device_param](../api/power_service/site/set_site_device_param.md) (param types 6 and 18).

#### Since/changed
3.18.0: setTacticsTime function size 0x36c4. 3.24.3: 0x34e0 (audit row 87, @0x2887ff4). The tag layout is the same in the cited builders.

#### Known unknowns
- Which of the four slot tags maps to `startTime`, `endTime`, `power`, `chargingPercentage` (audit rows 85-86 give the model fields only).
- Upstream describes `fd` as a millisecond timestamp (`mqttcmdmap.py` lines 163-169); the app writes a CRC32 (audit rows 24, 219-221). Which CRC parameters `ParametricCrc` uses is not documented.
- Upstream says the command must not be sent directly (cloud-driven).

#### Device-tested by
A17C1 FW 1.0.6.10, mqtt_monitor, usage modes 1 and 3 ([../devices/solarbank.md](../devices/solarbank.md); the audit's prose row 1 counts 005e among the commands confirmed against upstream). Date and client version not recorded.

### Opcodes without a confirmed app builder (005a, 0082, 006a, 0069)

#### Purpose
Opcodes the old doc or upstream lists for the Solarbank family that the 3.24.3 asm does not confirm as A17C1 builders.

#### Upstream name
`005a` is `CMD_SB_MAX_LOAD` with `sb_max_load_parallel` (`mqttmap.py` line 4993), upstream-confirmed; `0082`, `006a`, `0069` have no upstream name.

#### Command code
`"005a"`: no function in any A17C1 or A17C5 file and no `[0, 0x5a]` pool list in either version (audit row 222; the max-load write goes through 0080). `"0082"`: init command, pool list used at @0x226da44 in `sendCommandWithParam`. `"006a"`: pool list exists, no use found in `charging/ble` (audit row 235). `"0069"` is not an opcode: `hourPerMinute` @0x274e0b8 turns an "HH:MM" string into minutes and sends nothing (audit row 232). Tags: asm-traced (for what was found); UNVERIFIABLE rows go to Known unknowns.

#### Direction
app→device (005a upstream), not applicable for 0069.

#### Topic pattern
[envelope.md](envelope.md#topics): `cmd/anker_power/A17C1/<sn>/req`.

#### Payload fields
| tag | name | type | unit/scale | required | source |
|---|---|---|---|---|---|
| `a2` | `set_max_load` (005a) | 2 bytes (`sile`, upstream) | W; options 1200, 2400, 3600, 4800 (upstream) | upstream | upstream-confirmed (`mqttmap.py` lines 4993-5006) |
| `a3` | `set_max_load_type` (005a) | 2 bytes (`sile`, upstream) | default 2 (upstream) | upstream | upstream-confirmed (`mqttmap.py` lines 4993-5006) |

#### Example
none.

#### Related API endpoint
none (MQTT only).

#### Since/changed
No change recorded by the audit.

#### Known unknowns
- 005a: the app has no builder; the device-test table in [../devices/solarbank.md](../devices/solarbank.md) lists it as mqtt_monitor-tested, so a device may accept it (audit row 222 UNVERIFIABLE for the app side).
- 0082 (init) and 006a (peak-valley day data GET) labels are unconfirmed (audit row 235); the peak-valley day-data getter uses other lists (0x63, 0x2e, 0x64, 0x2f).

#### Device-tested by
005a: A17C1 FW 1.0.6.10, mqtt_monitor ([../devices/solarbank.md](../devices/solarbank.md)); date and client version not recorded.
