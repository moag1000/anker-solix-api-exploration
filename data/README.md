# Data

This directory holds the machine-readable exports of the repository: `endpoints.json`, `models.json`, `param_types.json` and `errors.json`. They are generated by the scripts in `tools/` from the 3.24.3 asm (and, for `errors.json`, the upstream `errors.py` and issue reports) and are never edited by hand. The prose pages cite them; this page is the contract for everyone who reads them with a program, for example the maintainers of the upstream [anker-solix-api](https://github.com/thomluther/anker-solix-api) library who want to diff the app's endpoint list, model keys, `param_type` ids or error codes against their own tables.

Not here: what a field means for the API (the owner pages under [../api/](../api/README.md), [../models/](../models/README.md) and [../api/errors.md](../api/errors.md) do that) or how the generators work (see [../tools/README.md](../tools/README.md)). Everything in these files is extracted evidence, not a verdict: the confidence of a fact is set on its owner page, and most rows are `string-only` until a page promotes them.

## Envelope (all files)

Every file is one JSON object with sorted keys, two-space indent and a trailing newline.

| Key | Type | Meaning |
|---|---|---|
| `generated_by` | string | Tool and arguments that produced the file |
| `app_version` | string | App version the asm came from (`3.24.3`) |
| `snapshot` | string | Identifier of the exact asm snapshot (the same value in all four files) |
| `rows` | list | The data; every row is an object |

The row schemas below are enforced by [`tools/schema_check.py`](../tools/schema_check.py) (field names and types, no unknown fields). Types are JSON types: `str`, `int`, `bool`, `list`, `dict`, `null`. A field written `str|null` is always present and may be `null`.

## Stability promise

- Keys are additive. A new field may appear in any row, and a new file or a new `source`/`kind` value may appear, in any release. Consumers must ignore fields they do not know.
- A field that is removed, renamed or changes its type is announced in the [CHANGELOG](../CHANGELOG.md) in the release that does it. Until then the field stays with the meaning given here.
- Row order is deterministic (sorted by the keys named per file) but not part of the promise; look rows up by their identity key.
- Row counts and values change when the app version changes. The `app_version` and `snapshot` keys say which asm a file describes; do not mix files with different values.
- Optional fields (listed as such below) are absent, not `null`, when they do not apply.

## endpoints.json

One row per URL string load found in the asm. Generator: `python3 -I tools/endpoint_inventory.py <asm_root> --version 3.24.3 --old-root <3.18.0 asm_root>`. Identity: `url` together with `dart_file`, `class`, `function` (one URL can have several rows, one per place that loads it).

Required fields:

| Field | Type | Meaning |
|---|---|---|
| `url` | str | Path with leading slash, for example `/power_service/v1/...` |
| `service` | str | First path segment of `url`, for example `power_service` (the directory under [../api/](../api/README.md)) |
| `url_addr` | str | Address of the URL string load (`0x...`) |
| `dart_file` | str | Dart file that loads the URL, relative to the asm root |
| `class`, `function` | str | Dart class and function that hold the literal |
| `addr` | str | Address of that function |
| `role` | str | `sender` (the function itself calls an HTTP primitive) or `url_provider` (it only holds the URL; see the `sender*` fields) |
| `since` | str | `≤3.18.0` (present in 3.18.0, earlier versions not checked) or `3.24.3` |
| `encrypted` | bool | Callee name contains `encryptionRequestHttp` |
| `encryption_note` | str\|null | Set for plain `requestHttp` callees, where the callee default `needEncryption = true` applies |
| `http_callees` | list[str] | HTTP callees seen in the function |
| `callers` | list[str] | `file::function` of the functions that call this one |
| `params` | list[str] | String literals that look like request parameter keys |
| `envelope` | list[str] | Envelope keys seen next to the call |
| `param_data_is_json` | bool | `param_data` is built as JSON in the function |
| `param_type`, `param_type_source` | str\|null | `param_type` id found in the function and how (`literal` or `variable`); `variable` means the id is stored from a register and is not decoded here |
| `cmd`, `cmd_addr`, `cmd_raw`, `cmd_note` | int\|null, str\|null, int\|null, str\|null | Command id of a `set_site_device_param` style call after the Smi rule (`cmd_raw` is the immediate before halving), with its address; `cmd_note` is reserved and currently always `null` |
| `upstream_key` | str\|null | Key in upstream `API_ENDPOINTS` (`apitypes.py`) that has the same path, if any |

Optional fields:

| Field | Type | Meaning |
|---|---|---|
| `sender` | str | `Class::function @0xADDR` of the nearest function that sends after the URL load |
| `sender_file` | str | Dart file of `sender` |
| `sender_kind` | str | `self` (the function holds the primitive call), `wrapper` (the sender is the helper it calls) or `callee` |
| `sender_wrapper` | str | HTTP primitive or wrapper symbol that is called |
| `sender_via` | list[str] | Callers walked from the provider up to the sender, excluding the provider (`[]` = the provider itself) |
| `sender_via_files` | list[str] | Dart files of `sender_via` |
| `sender_via_also` | list[list] | Other call chains to the same sender |
| `sender_also` | list[str] | Other senders at the same depth (at most 5) |
| `resolution` | str | Set when no sender was found: `generic-path-check`, `mixin-gap` (unconfirmed) or `unresolved` |
| `reference` | str | `pool-only`: the string is in the 3.24.3 object pool but no code loads it |
| `removed_in` | str | Version whose object pool no longer holds the string (set only for URLs absent from the pool) |

The `sender*` fields are string-level evidence: a caller that sends may send something else than this URL.

## models.json

One row per Dart class with a `fromJson` factory or constructor. Generator: `python3 -I tools/model_fields.py <asm_root> --version 3.24.3 --old-root <3.18.0 asm_root> [--include-noise]`. Identity: `key`, which is unique in the file.

Required fields:

| Field | Type | Meaning |
|---|---|---|
| `key` | str | `package::Class`; see below |
| `class` | str | Short class name (not unique: 110 names occur in more than one file) |
| `dart_file` | str | Dart file, relative to the asm root |
| `from_json_addr` | str | Address of the `fromJson` function |
| `since` | str | `≤3.18.0` or `3.24.3`, as for endpoints |
| `removed_keys` | list[str] | JSON keys the class had in 3.18.0 and no longer reads |
| `fields` | list[object] | One object per JSON key, in read order (below) |

Optional: `removed_in` (str), set for a class that existed in 3.18.0 and has no counterpart in 3.24.3 (its `fields` are the 3.18.0 ones).

Each `fields` entry has `json_key` (str), `dart_type` (str, `unknown` when no cast was seen), `nullable` (bool\|null, `null` = the extractor could not tell), `key_addr` (str, address of the key string load) and `since` (str\|null).

`key` is the package (first directory of `dart_file`) and the class name. Where two classes would still share that key, the package part is extended to the shortest unique directory path and, if needed, to the file path without `.dart`, for example `charging/model/a5101::Power` and `charging/model/a1782::Power`. The result is unique in every file this tool writes (no collisions). A key is stable while the Dart file stays where it is; a moved file is a changed key, announced like any other change.

Noise filter: dropped by default are the 15 classes of the `sentry` package (the error-reporting SDK; 11 without fields, 4 with). `--include-noise` keeps them. Field-less app classes are kept with an empty `fields` list (5 in 3.24.3): a field-less `fromJson` may be an extractor limit rather than a class without keys, so consumers should see that the class exists. Keys do not depend on the flag.

## param_types.json

One row per `param_type` id the app sends to `set_site_device_param` style endpoints. Generator: `python3 -I tools/param_types.py <asm_root> --version 3.24.3`. Identity: `param_type`. All fields are always present.

| Field | Type | Meaning |
|---|---|---|
| `param_type` | str | The id as the app writes it (usually numeric) |
| `param_type_source` | str | `literal`, `traced` or `variable` (how the id was found) |
| `name` | str\|null | Upstream `SolixParmType` name, `null` when upstream has none |
| `cmd`, `cmd_addr`, `cmd_raw` | int\|null, str\|null, int\|null | Command id after the Smi rule, its address and the raw immediate |
| `cmd_set`, `cmd_set_addr`, `cmd_set_raw` | same | Command id of the setter path |
| `cmd_get`, `cmd_get_addr`, `cmd_get_raw` | same | Command id of the getter path, `null` when the getter sends none |
| `cmd_by_function` | dict | Function name to command id |
| `function_sources` | dict | Function name to how it was resolved (`literal`, `traced`, `variable`) |
| `set_function`, `get_function` | list[str] | Functions that write or read this type |
| `get_model` | str\|null | Model class of the getter response, when known |
| `dart_files` | list[str] | Dart files involved |
| `keys` | list | Parameter keys written for this type (strings, or objects with the decoded key) |
| `traced_from` | list | Trace steps for ids found by tracing |
| `unresolved` | list | Keys or sites the tool could not resolve |

## errors.json

One row per error code occurrence. Generator: `python3 -I tools/error_codes.py [--check]` (the output path is fixed). Identity: `code` together with `source` and, for asm rows, `function_addr`/`addr`. Always present: `code` (int), `source` (str), `kind` (str) and `tag` (str, one of the confidence tags).

| `source` | `tag` | Fields beyond the common ones |
|---|---|---|
| `upstream` | `upstream-confirmed` | `name`, `base`, `message`, `file`, `line`, `class_line` (entry in upstream `api/errors.py`) |
| `asm` | `asm-traced` | `file`, `function`, `function_addr`, `addr`, `width`, `form`, `raw`, `odd_raw`, `branch` (str\|null), `strings` (the localization keys or log text next to the compare) |
| `issue` | `device-tested` | `name`, `endpoint`, `context`, `url`, `reported_by`, `reported` |

`kind` is `api` (an error code the catalog page is about) or `message-type-excluded` (a compare of a device message type that shares numbers with API codes; kept as data, never counted as a code). The Smi decoding of the `asm` rows is explained in [../METHODOLOGY.md](../METHODOLOGY.md).

## Validation

```bash
python3 -I tools/schema_check.py --check     # exit 1 on any violation, writes nothing
```

The check covers the envelope, the required and optional fields above with their types, unknown fields, unique `models.json` keys, and that all four files carry the same `app_version` and `snapshot`. When a generator gains a field, add it to the schema in `tools/schema_check.py` and to the table here in the same change; the CHANGELOG announces only removals and renames.
