# A17C5 MQTT commands (differences from A17C1)

Solarbank 3 (A17C5) uses the same app controller and the same status parser family as the Solarbank 2 (A17C1). This page states only the differences and links the owner pages for everything shared: SET opcodes and their tags are on [a17c1.md](a17c1.md), the 0405 field handling on [a17c1_status.md](a17c1_status.md), the frame and topics on [envelope.md](envelope.md).

Evidence rows are written `audit row N` and refer to [../docs/audit/BLE_COMMAND_MAP.md](../docs/audit/BLE_COMMAND_MAP.md) (rows 637-648 are the A17C5 section); `file.dart @0xADDR` is 3.24.3 asm. Upstream names win: A17C5 names are from `_A17C5_0405` (`api/mqttmap.py` lines 2138-2212) and A17C1 names from `_A17C1_0405` (lines 1796-1863). A device-level product page exists at [../devices/a17c5.md](../devices/a17c5.md).

## Commands

### 0405 status differences from A17C1

#### Purpose
Lists which tags the A17C5 parser reads compared with the A17C1 parser and how upstream names them for each product.

#### Upstream name
`_A17C5_0405` (topic `param_info`), upstream-confirmed (`mqttmap.py` lines 2138-2212; bound at line 5208).

#### Command code
`"0405"`, parsed by `A17C5DeviceCommands.parseDeviceAllInfo` @0x4860fec (size 0x35c0). Asm-traced.

#### Direction
device→app. Tag: asm-traced.

#### Topic pattern
[envelope.md](envelope.md#topics): `dt/anker_power/A17C5/<sn>/param_info`.

#### Payload fields
The tag sets below are the `indexString` arguments of both parsers (3.24.3 and 3.18.0 identical, audit row 637). The same tag number can mean different things per product in upstream's maps; the name cell shows both. The scale column is upstream's FACTOR for A17C5 (`-` means upstream defines none). The A17C1 parser divides several power tags (see [a17c1_status.md](a17c1_status.md#payload-fields)); the audit did not trace the A17C5 divisors, so the A17C5 scales are open (see Known unknowns).
