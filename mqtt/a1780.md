# A1780 positional status parser (F2000)

SOLIX F2000 (A1780): the fixed-position decoders of the status buffer (`parseOtherData`, `parseSwitchData`, `parseCountdownData`, `parseDeviceInfo`). The tag-based `0405` message of the same device is an upstream map (`_A1780_0405`, `mqttmap.py` lines 890-951) and is not a decoder in the app files audited here. The envelope, topics and frame layout are owned by [envelope.md](envelope.md); the PPS setters by [a172x.md](a172x.md); A1781 (F2600) is covered by the note on [a1753.md](a1753.md).

Evidence rows are written `audit row N` and refer to [../docs/audit/BLE_COMMAND_MAP.md](../docs/audit/BLE_COMMAND_MAP.md); `file.dart @0xADDR` is 3.24.3 asm. The audit found the old doc's `Pos` column wrong in all 46 rows (every value was a tagged end offset, so the real value is half of it); this page uses the audit's corrected byte windows. Store offsets are Blutter byte offsets, not Smi-affected. Names are upstream's where the tag has one; a name of ours is marked `(no upstream name)`.

## Parsers

### parseOtherData (positional status block)

#### Purpose
Decodes the main status block of an A1780 (F2000) from fixed byte positions: power values, firmware parts, temperatures, SOC and the switch states.

#### Upstream name
No upstream name for the positional parser. The tag numbers and names in the table are the old doc's order-based mapping onto the tag map `_A1780_0405` (`mqttmap.py` lines 890-951, bound for A1780, A1780P and A1781 at lines 4604, 4633 and 4666), upstream-confirmed for the names of that map only.

#### Command code
No command code: the parser takes a byte list and reads `sublist(start, end)` windows. `A1780Commands.parseOtherData` @0x45ebfcc (size 0x1664, first block @0x45ebffc) in `charging/ble/device/A1780/a1780_commands.dart`; the F1200 (A1770) file `a1770_commands.dart` has its own copy @0x45e9ec0 (size 0x1310). Asm-traced for the windows, widths and store offsets.

#### Direction
device→app. Tag: asm-traced for the parser direction (a status parser); the transport is not in the audit (see Known unknowns).

#### Topic pattern
Not applicable to the positional parser: the audit does not bind it to an MQTT topic. The tag-based `0405` message of A1780 is on [envelope.md](envelope.md#topics) (`dt/anker_power/A1780/<sn>/param_info`, upstream-confirmed).

#### Payload fields
The first two blocks are 4 bytes wide, the blocks up to start 63 are 2 bytes, and the blocks from start 65 on are 1 byte (audit rows 517, 518). In the asm each block loads `r2` = start and `r16` = end as Smi (end raw / 2); the old doc had the two roles swapped and wrote the end offsets in tagged form (all 46 old `Pos` values were wrong, audit row 518). Every block is read with `sublist(start, end)`, and the next start equals the previous end. The tag and name columns are the old doc's mapping by order; the asm has no tag numbers in this parser. The audit corrected two blocks: row 552 (the old doc offset 0x3D3 belongs to the neighbouring block, audit row 551) and the duplicate `bd` (row 543 and row 547 carry the same old tag; the block at [61, 63) stores a raw value and a `getMainVersion()` string, audit row 544).

- Unknown windows (audit rows 532, 533, 537-542, 549, 551, 554, 562, 563): no upstream name for any of them.
