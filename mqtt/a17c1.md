# A17C1 MQTT commands

Solarbank 2 Pro/Plus (A17C1) over MQTT: the SET opcodes the 3.24.3 app builds for this product. The 0405 status message and the status/realtime requests are on [a17c1_status.md](a17c1_status.md) (split off to stay under 600 lines). The A17C3 and A17C2 products share the controller functions; A17C5 (Solarbank 3) differences are on [a17c5.md](a17c5.md). The envelope, topics, frame layout and the data type codes are owned by [envelope.md](envelope.md) and not repeated here.

Evidence rows are written `audit row N` and refer to [../docs/audit/BLE_COMMAND_MAP.md](../docs/audit/BLE_COMMAND_MAP.md); `file.dart @0xADDR` is 3.24.3 asm. Opcodes are the hex strings of the Dart source (pool lists `[0, 0x5e]` are the same two bytes, never halved); field keys come from `r2 = 324` style immediates that are halved (324 is tag `a2`), per the Smi rule in [../METHODOLOGY.md](../METHODOLOGY.md#smi-rule-reading-numbers-from-blutter-output). Names are upstream's (`api/mqttmap.py`, `api/mqttcmdmap.py`); a name of ours is marked `(no upstream name)`. All SET commands are sent as `normalCommand` through the generic frame with an `FE` timestamp trailer unless the command says it writes the `FD` CRC trailer. Controller file for every SET row: `charging/ble/device/A17C1/a17c1_device_controller.dart`.

| `a3` | `set_timestamp_a3_or_0?` | 1 byte | flag | yes | audit row 218; @0x281a610; upstream-confirmed (`mqttcmdmap.py` line 861) |
| `a4` | `set_backup_charge_switch` | 1 byte | switch | yes | audit row 218; @0x281a658; upstream-confirmed (`mqttcmdmap.py` line 865) |
| `a6` | `set_timestamp_backup_start` | 4 bytes | timestamp | yes | audit row 218; @0x281a698; upstream-confirmed (`mqttcmdmap.py` line 880) |

| `fd` | (no upstream name for this use) | 4 bytes | CRC32 of the payload | yes | audit row 219; @0x281aa44..0x281aa94 (key raw 506) |

setPeakValley (audit row 221): `a2` mode and `a3` flag @0x428a888, @0x428a8c8, then the CRC32 under `fd` @0x428b058..0x428b0a8.

setTacticsTime (audit rows 84, 88, 220): 29 data tags `a2` to `be` (keys raw 324..380 halved; the array length raw 116 is 58 elements = 29 key/value pairs @0x288ac88) followed by the CRC32 under `fd` @0x288b238. The data tags are one mode tag plus seven slots of four tags; each slot is a `DischargeTimeModel` with four integer fields (class size 0x20): `startTime` 0x8, `endTime` 0xc, `power` 0x10, `chargingPercentage` 0x14 (audit rows 85-86, `pps_device_feature.dart` class header). The old doc said 14 slots and 30 tags plus a timestamp; both were raw Smi readings (audit rows 84, 88).

#### CRC parameters of fd
New read 2026-10-20 (`setBackPower` @0x281a588). The builder allocates `Crc32` (`AllocateCrc32Stub` @0x281aa44) and calls `ParametricCrc` @0x23bf998 with the unboxed arguments 4294967295 and 4294967295 (`mov x2,#0xffffffff` @0x281aa4c, `mov x3,#0xffffffff` @0x281aa50, 64-bit, real values: seed and final mask). The constructor `ParametricCrc` (crclib/src/model.dart @0x23bf998, size 0x118) stores the polynomial 79764919 (`mov x3,#0x1db7; movk x3,#0x4c1,lsl #16` = 0x04C11DB7, 64-bit unboxed @0x23bf9dc), the width 32 (`mov x1,#0x20`, 64-bit store at offset 0xb @0x23bfa04) and the bool `true` at offset 0x2f (@0x23bf9f8, the reflection flag of the CRC variant); `Crc32` extends `Crc32IsoHdlc` (crclib/catalog.dart class header, class id 15756). So the app computes the standard CRC-32 (ISO-HDLC variant, polynomial 0x04C11DB7, initial value and final xor 0xFFFFFFFF) over the payload list (`convert` @0x281aa64), turns the `CrcValue` into text with `toRadixString` and parses it back with `int.parse` (default radix, descriptor `[0, 0x1, 0, 0x1, null]` @0x281aa74) before `intToList4`; the digit text is the decimal rendering of the value (radix argument not passed). The other builders with `fd` (`setPeakValley`, `setTacticsTime`) call the same classes (@0x428b0a8, @0x288b238); which payload bytes enter the CRC was only read for `setBackPower`, where it is the list assembled by the loop that precedes @0x281aa3c.

#### Example
synthesized. The CRC bytes are not computed.

```text
ff 09 <len> 03 00 0f 00 5e | a1 01 22 | a2 02 01 <mode> | a3 02 01 00 | a4 02 01 <0|1> | a6 05 03 <start> | a7 05 03 <end> | fd 05 03 <crc32> | xor
```

#### Related API endpoint
Schedule writes through the cloud: [set_site_device_param](../api/power_service/site/set_site_device_param.md) (param types 6 and 18).

#### Since/changed
3.18.0: setTacticsTime function size 0x36c4. 3.24.3: 0x34e0 (audit row 87, @0x2887ff4). The tag layout is the same in the cited builders.

#### Known unknowns
- Which of the four slot tags maps to `startTime`, `endTime`, `power`, `chargingPercentage` (audit rows 85-86 give the model fields only). — traced 2026-10-20: `setTacticsTime` @0x2887ff4 (size 0x34e0) builds the slots in a loop with generic list calls (`GDT[cid_x0 + 0x348e1]` element reads at indexes 0, 2, 4, 6, 8, 10, 12 @0x288848c..0x2888624 and `intToList` with unboxed zero arguments @0x288803c..0x28880d8); the per-slot tag-to-field binding is not recoverable from the compares and loads seen without a full register trace.
- Upstream describes `fd` as a millisecond timestamp (`mqttcmdmap.py` lines 163-169); the app writes a CRC32 (audit rows 24, 219-221). The CRC parameters are stated below the table ([CRC parameters of fd](#crc-parameters-of-fd)); what bytes feed it per builder is only traced for `setBackPower`.
- Upstream says the command must not be sent directly (cloud-driven).

#### Device-tested by
A17C1 FW 1.0.6.10, mqtt_monitor, usage modes 1 and 3 ([../devices/solarbank.md](../devices/solarbank.md); the audit's prose row 1 counts 005e among the commands confirmed against upstream). Date and client version not recorded.

### Opcodes without a confirmed app builder (005a, 0069)

#### Purpose
Opcodes the old doc or upstream lists for the Solarbank family that the 3.24.3 asm does not confirm as A17C1 builders. `005a` and `0069` stay here; `0082` and `006a` were listed here by the old doc but are app senders (a2 = 1, see the Known unknowns), so they only appear in this section as a record of that correction.

#### Upstream name
`005a` is `CMD_SB_MAX_LOAD` with `sb_max_load_parallel` (`mqttmap.py` line 4993), upstream-confirmed; `0082`, `006a`, `0069` have no upstream name.

#### Command code
`"005a"`: no function in any A17C1 or A17C5 file and no `[0, 0x5a]` pool list in either version (audit row 222; the max-load write goes through 0080). `"0082"`: pool list used at @0x226da44 in `setOnGridOverPowerRecovery` @0x226d9a8 (the audit called it an init command and placed it in `sendCommandWithParam`; re-read 2026-10-20, see the Known unknowns). `"006a"`: pool list used at @0x3b567d8 in `deviceFactorySettingClear` @0x3b5673c (audit row 235 found no use in `charging/ble`; re-read 2026-10-20 finds this one, so the heading's "no confirmed app builder" holds only for `005a`). `"0069"` is not an opcode: `hourPerMinute` @0x274e0b8 turns an "HH:MM" string into minutes and sends nothing (audit row 232). Tags: asm-traced (for what was found); UNVERIFIABLE rows go to Known unknowns.

#### Direction
app→device (005a upstream), not applicable for 0069.
