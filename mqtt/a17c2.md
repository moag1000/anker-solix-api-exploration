# A17C2 MQTT commands (Solarbank 2 AC)

Solarbank 2 E1600 AC (A17C2): the 0405 status message and the list of setters it shares with [a17c1.md](a17c1.md). The A17C1 status layout is owned by [a17c1_status.md](a17c1_status.md); the envelope, topics, frame layout and data type codes by [envelope.md](envelope.md).

Evidence rows are written `audit row N` and refer to [../docs/audit/BLE_COMMAND_MAP.md](../docs/audit/BLE_COMMAND_MAP.md); `file.dart @0xADDR` is 3.24.3 asm. Tag keys are halved Smi immediates (per the Smi rule in [../METHODOLOGY.md](../METHODOLOGY.md#smi-rule-reading-numbers-from-blutter-output)); store offsets are Blutter byte offsets. Names are upstream's (`api/mqttmap.py`); a name of ours is marked `(no upstream name)`. The header tag is `string-only` because the field labels come from debug strings.

## Commands

### 0405 status message (param_info)

#### Purpose
Periodic status of a Solarbank 2 AC (A17C2): battery, grid-connected and off-grid port power, energy counters and the grid-collapse flag.

#### Upstream name
`_A17C5_0405` (topic `param_info`, `mqttmap.py` lines 2138-2211), bound for A17C2 at line 5083 together with `_A17C0_0407` and `_A17C5_0408` (lines 5085, 5087), upstream-confirmed. The names in the table differ from the debug-string labels; both are shown.

#### Command code
`"0405"`, parsed by `A17C2DeviceCommands.parseDeviceAllInfo` @0x485d724 (size 0x38c8; `charging/ble/device/A17C2/a17c2_device_commands.dart`). `A17C2AnkerDevice` extends `A17C1AnkerDevice` (class header, `a17c2_anker_device.dart` line 8); there is no A17C2 controller file in 3.24.3. Asm-traced for the parser and the tag numbers.

#### Direction
device→app. Tag: asm-traced.

#### Topic pattern
[envelope.md](envelope.md#topics): `dt/anker_power/A17C2/<sn>/param_info`.

#### Payload fields

#### Related API endpoint
none (MQTT only).

#### Since/changed
Both versions read the same tags. Store offsets moved (audit rows 345, 346): `ae` 0x21b to 0x227, `af` 0x21f to 0x22b. Changed since 3.18.0.

#### Known unknowns
- Which meaning applies: the debug-string labels (`ab` total output power, `c2` total input power) conflict with the upstream names via the A17C5 map (`ab` `photovoltaic_power`, `c2` `photovoltaic_power?`, `ac` `battery_power_signed`, `ae` `ac_output_power_signed`, `b0` `pv_yield`, `b1` `charged_energy`). Recorded two-sided; neither is traced to a value store.
- No upstream name for `af` and `d3`.
- Type, width and scale of the tags (audit rows 342-349 are tag-level except the two `hexStringToDouble` rows).
- The old doc label for `d3` came from a comment-style text (`标识当前是否0溃网`) that is not in `pp.txt`; the app string is `A17C2 是否0溃网 D3:` @0x4860cd4.

### Setters (shared with A17C1)

#### Purpose
Lists the SET opcodes that upstream binds for A17C2 and where the app builders are documented.

#### Upstream name
Bound for A17C2 in `SOLIXMQTTMAP` (`mqttmap.py` lines 5043-5090); the constants are described on [upstream_commands.md](upstream_commands.md).

#### Command code
The app has no A17C2 controller file (`charging/ble/device/A17C2/` holds only the device class and the commands file), and `A17C2AnkerDevice extends A17C1AnkerDevice`, so the builders of [a17c1.md](a17c1.md) are the candidates; the binding of A17C2 to them was not read in the audit. Opcode strings, tags and addresses are owned by [a17c1.md](a17c1.md); this page repeats none of them.

#### Direction
app→device. Tag: upstream-confirmed for the bindings.

#### Topic pattern
[envelope.md](envelope.md#topics): `cmd/anker_power/A17C2/<sn>/req`.
