# A1753 MQTT commands (C800, with an A1781 note)

SOLIX C800 (A1753): the three tags it adds to the A1771 status message. The base tags are owned by [a1771.md](a1771.md); the PPS setters by [a172x.md](a172x.md). The envelope, topics, frame layout and data type codes are owned by [envelope.md](envelope.md).

Evidence rows are written `audit row N` and refer to [../docs/audit/BLE_COMMAND_MAP.md](../docs/audit/BLE_COMMAND_MAP.md); `file.dart @0xADDR` is 3.24.3 asm. Tag keys are halved Smi immediates (per the Smi rule in [../METHODOLOGY.md](../METHODOLOGY.md#smi-rule-reading-numbers-from-blutter-output)); store offsets are Blutter byte offsets.

## Commands

### 0405 extra tags e5, f8, f9 (A1753)

#### Purpose
Adds the backup-charge switch, the two port saving modes and one extension field to the A1771 status message of a SOLIX C800 (A1753).

#### Upstream name
`backup_charge_switch` (`mqttmap.py` lines 367 and 937) and the `f8` byte names `dc_12v_output_mode` and `ac_output_mode` (lines 368-378) from the sibling maps; there is no `A1753` key in `SOLIXMQTTMAP` (upstream lists A1753 as C800 in `apitypes.py` line 689 and `mqtt_pps.py` line 26), so the names are upstream-confirmed for A1761 and A1780 only.

#### Command code
`"0405"`, parsed by `A1753DeviceCommands.parseDeviceAllInfo` @0x484f170 (size 0x5c4; `charging/ble/device/A1753/a1753_device_commands.dart`); the file also has `parseSubPackageData` @0x484f734, `parseSwitchStateInfo` @0x4857884 and `parseWorkInfo` @0x4859ccc (function start from the asm header, not in the audit). The class `A1753AnkerDevice` extends `A1771AnkerDevice` through a mixin (class header, `a1753_anker_device.dart` line 8), so the base tags are those of [a1771.md](a1771.md). Asm-traced.

#### Direction
device→app. Tag: asm-traced.

#### Topic pattern
[envelope.md](envelope.md#topics): `dt/anker_power/A1753/<sn>/param_info`.

#### Payload fields

#### Work info and sub-package
New read 2026-10-20 (`a1753_device_commands.dart`). `parseWorkInfo` @0x4859ccc (size 0x11c) calls `A1771DeviceCommands.parseWorkInfo` first, then reads `e5` (bool, true when the 64-bit `listToInt` result equals 1, `cmp x0,#1`, stored at offset 1023) and calls `parseSubPackageData` (call after @0x4859d40). `parseSwitchStateInfo` @0x4857884 (size 0x12c) calls `A1771DeviceCommands.parseSwitchStateInfo` and then does the same `e5` store at offset 1023 (@0x485792c). `parseDeviceAllInfo` @0x484f170 ends with the same `parseSubPackageData` call. `parseSubPackageData` @0x484f734 (size 0x238) reads one tag, `fd` (`indexString` argument 253 @0x484f750): when the entry is absent (`cmp w0, NULL` @0x484f778) it stores false at offset 771 and clears the list at offset 395; when present it stores true at offset 771, decodes the entry as UTF-8 text (`Utf8Decoder.convert` @0x484f7ec) and, if the 32-bit field at offset 763 is non-zero (`cbz x3` @0x484f814), builds a one-element `SubPackageModel` list (`getMainVersion` @0x484f820, constructor with three named arguments @0x484f840; `AllocateArray` r2 = 2, a tagged length, so 1 element) and stores it at offset 395, otherwise it clears that list. So in this app the tag `fd` of an A1753 status frame is read as sub-package text, not as the CRC32 timestamp slot of the command side ([envelope.md](envelope.md#tlv-frame)); it is app side only and no device was checked.

#### Example
synthesized. `f8` with four bytes (a 4-byte value uses data type 3, see [envelope.md](envelope.md#data-type-codes)); not a capture.

```text
a1 01 22 | e5 02 01 01 | f8 05 03 02 01 01 00 | f9 02 01 <v> | fe 05 03 <ts 4 bytes> | xor
```

#### Related API endpoint
none (MQTT only).

#### Since/changed
The tags `e5`, `f8`, `f9` exist in both versions. Store offsets moved (audit rows 312-314): `e5` 0x3f3 to 0x3ff; `f8` 0x197 and 0x19b to 415, 419, 423, 427; `f9` 0x42b to 0x437. Changed since 3.18.0.

#### Known unknowns
- The `f8` mapping to the two upstream bytes (`dc_12v_output_mode`, `ac_output_mode`) rests on upstream names and the enum shape; the byte-to-offset order is traced (table above: bytes [0] and [1] are the two enum fields at offsets 415 and 419), the field names behind those offsets are not (getter selectors not read). — traced 2026-10-20: a1753_device_commands.dart @0x484f170..@0x484f540.
- A1781 (F2600): `charging/ble/device/A1781/` has no commands file; `A1781AnkerDevice extends A1771AnkerDevice` (class header, `a1781_anker_device.dart` line 8), so the A1771 parsers apply. Upstream binds A1781 to `_A1780_0405` (`mqttmap.py` line 4666). No audit row covers A1781; its 0405 tag set is not documented here.
- The A1753 `parseWorkInfo` @0x4859ccc and `parseSwitchStateInfo` @0x4857884 read only `e5` themselves (see [Work info and sub-package](#work-info-and-sub-package)); the tag `fd` meaning for a device is not traced.
